# 初始化 lody4dot 接入

这是用户主动运行插件 setup 后的引导入口。先读取[核心技能](../lody4dot/SKILL.md)，再按需读取[准备与身份规则](../lody4dot/references/setup-cloud.md)和[多宿主协作](../lody4dot/references/collaboration.md)；通用命令知识以这些资料为准。

本技能不是安装时自动运行的脚本，也不是 Dot 或 Codex 的存储重置 hook。已发布的云环境准备脚本、任务启动指引与本次 setup 分别记录，不能互相冒充加载证据。

## 识别本次执行位置

1. 记录实际宿主及工具执行器，区分 Work 的本地/托管执行、Dot 自有云电脑、Codex 云任务和获授权的本地电脑；不要用对话所在产品推断 shell 所在机器。Work Cloud 不自动采用 GitHub 编码环境、Codex 准备脚本或本地 STDIO 配置，先看[宿主与任务入口](../lody4dot/references/collaboration.md#work-cloud与任务创建)。
2. 查看本端实际提供的 shell、OS、Python、Node/npm、Lody CLI 或宿主注入的 Lody MCP。CLI 不在 PATH 中不代表没有宿主工具；没有暴露的工具不补造。
3. 定位本次插件文件。自包含包的工具在插件根 `scripts/`；仓库副本在仓库根 `plugin/lody4dot/scripts/`。核实实际文件及本端安装回执，再选择已存在的入口。只有技能资料时，保留知识接入，不执行不存在的脚本。
4. 复用当前任务已有授权和明确目标。需要依赖准备时，选择本端可写且所属明确的 prefix；已有安装以其回执为准，新安装使用独立目录，不覆盖陌生非空目录。其他宿主不套用云端的 `/workspace` 路径，也不复制另一端身份。

## 选择可执行的准备路线

| 本端实际条件 | 行动 |
| --- | --- |
| Linux，且具备工具所需 Python、Node/npm 和自有 prefix | 复用随包 `bootstrap.py`，按下方步骤检查或准备依赖。 |
| 已有合法 Lody app/MCP 或其他已验证入口 | 按核心技能核对实际工具、目标和已授予范围；不因换产品重复连接。工具连接与本端受管 CLI 安装分别报告。 |
| Darwin、原生 Windows、其他未验证平台，或没有 shell/运行前提 | 不尝试受管安装；按已提供能力选择现成合法工具、已准备 Codex 环境的委托路线或知识交接。委托仍需实际任务入口和授权，不自动创建任务。 |
| 仅能读取技能 | 完成知识入口说明，工具调用、控制和执行保持未验证，并列出所缺的实际入口。 |

受管 runtime 当前仅验证 Linux。具体 Python/Node 前提及其他平台边界见准备资料和当前插件 README，不把 OS 分支模拟当作真实跨平台安装。

有本端工具时，先从对应工作目录查看 `bootstrap.py --help`。仓库工作目录使用 `python3 plugin/lody4dot/scripts/bootstrap.py`，自包含包工作目录使用 `python3 scripts/bootstrap.py`；后续参数相同：

- 仅检查：传入 `--prefix` 和已核实的本端绝对路径，再传 `--json`，不加动作参数。
- 当前请求已授权依赖初始化：按目标选择 `--prepare`，或选择先检查、只修复缺失受管依赖的 `--repair-missing`；两者互斥。安装阶段在暂存目录定向更新lody锁、解析官方npm latest，遵守engine-strict、禁用生命周期脚本及保留的依赖约束，验证成功后切换；实际版本由收据记录，不把文档中的版本当未来latest。已有授权足够时直接继续，不要求用户重复确认。
- `--repair-missing` 只处理明确的 `missing_runtime`；来源损坏、陌生目录、平台或真实命令失败按实际错误处理。Lody 版本不同、版本探测失败仅 warn，不触发重装或阻塞后续可执行流程。默认检查离线，不自动查询更新或升级。

依赖准备不包含登录、注册 machine、启动 daemon、创建模型任务或恢复/重发旧业务。需要进一步认证或控制验收时，另按核心技能与本次已有授权执行，保持每端私密身份独立；不要输出凭证或将登录态放入插件包、共享快照。

准备后按[初始化与任务前预检](../lody4dot/references/setup-cloud.md#初始化与任务前预检)核实际CLI入口的版本、帮助和本次用途；复用已完成的相同检查，只发现缺少的目标。命令参数以当前`--help`及所需子命令帮助为准，不另建命令表。当前随包帮助为0.108.1，不证明本端业务可用；没有明确工作区或合法现有身份时列出缺项，不自动登录、创建配置或派发Agent。

## 给出范围明确的 setup 回执

简洁报告宿主/执行器、实际读取入口、CLI 实际版本或未知、prefix、所选动作、退出结果和 warn。分别列明知识是否可读、依赖是否检查/准备，以及认证、控制、执行、业务恢复各自结果；没有执行的项目写 `not_run`，不能从 bootstrap 通过推导成功。

附上一个基于真实可用入口的下一步。缺前提时说明具体缺口并继续已有能力范围内的工作；保存 setup 回执不等于已验证平台原生调用本技能、独立云任务首次加载或 Dot 生命周期事件。
