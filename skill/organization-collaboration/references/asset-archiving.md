# 项目资产归档与交付

安排项目资料、脚本、配置或媒体的归档、用途副本、交付与恢复时按需读取；普通编辑保存不额外触发归档流程。复用项目现有仓库、存储和正式任务记录；归档不自动授权上传、公开、迁移、删除、安装或执行脚本，不新建归档服务。前提未确认只暂停依赖动作，已有授权的独立工作继续。

## 按用途选落点

先核用途、维护来源、体积、数量、变化频率、访问范围和恢复要求，再选已获准落点；不能只按扩展名禁止媒体，也不能把小文件一律视为适合入库。

| 对象与用途 | 默认判断方式 |
| --- | --- |
| 文档、方案、台本、索引、复核报告 | 放项目已采用的文档／仓库入口；链接与提取摘要标明来源和覆盖，不能冒充完整原件。 |
| 源码、脚本、配置模板、依赖锁及复建说明 | 随维护源码版本管理；去除凭证、敏感配置和运行缓存。归档脚本不表示已获准执行或安装。 |
| 用于文档、演示或约定交付的小媒体 | 公开范围明确、体积和增长合适时可进入获准项目仓库；保留来源及用途，沿既定检查和交付约定。 |
| 大型、成批或频繁替换的素材、母带、模型、构建／分发产物 | 优先沿已确认的原存储或工件入口，索引保留准确引用及取得方式；不默认新增付费存储、LFS或转码。 |

项目／组织可以限定某协作空间只存文档和索引，这是采用政策，不是平台能力结论。工具上传入口、当前限制和目标访问能力在具体任务中核实；Git归档不替代已约定附件发送、试听或其他交付。环境仓库不提交凭证、依赖缓存和安装／分发生成物；图源随附文档SVG等既有例外继续按项目规则处理。

初始化／恢复脚本随附操作系统、依赖版本、工作目录、前提与参数、验证和恢复方法，说明安装、下载、联网、写系统或重启等副作用；保存这些说明不授权执行。源码与环境仓库默认排除完整虚拟环境、缓存、模型权重、临时日志和无保留价值的中间物，所需原件沿上表确认保管入口。

## 维护来源、用途副本与保管

明确可修改的维护来源与当前写者，副本记录用途及上游精确版本。发现副本需修订时沿维护来源处理或取得明确接管，不默默产生第二份独立维护的“正式版”。原件、同字节副本、预览、转码、提取文本和摘要分别标识；不同表示各记自身实际字节摘要，不能拿原件hash为预览或转码背书。同字节只支持内容一致，不继承新目标的公开或访问授权。

原件默认留已确认的保管位置。记录原件保管责任人、所属执行器、准确路径／原生对象、持久性与可用的恢复入口；隐私位置放受控记录。仅存临时位置、会话附件持久性未证实，或只有单份且缺恢复入口时如实记缺口，不能宣称可恢复。清理或交接前核保管承接及恢复入口；未获迁移、覆盖或清理授权的旧存档与用户文件保持原位。

分开陈述以下证据：

- **归档说明已保存：** 能定位来源、关系和所需步骤；不表示原件已取得。
- **原件可取得：** 指定读取方实际取得明确版本的原件字节，并有位置、版本与读取证据；不表示已验证恢复／复建。
- **恢复／复建已验证：** 记录实际输入、环境、步骤、结果和未覆盖范围。依赖锁与配方不证明外部模型、素材或服务仍可取得；这些输入需精确引用并核获取条件。生成结果也不默认可逐字节重现。

缺恢复或复建条件时，交负责人决定是否补齐及对应落点；不自动建备份、复制全部素材或运行复建。

## 权限、秘密与软阈值

复用仍有效且覆盖本批对象、用途和目的地的授权；核目标实际可见性及接收者范围，不能以私有看板或旧副本权限替代目标权限。标题、路径、原生会话和链接也可能敏感；公开索引只保留获准信息，精确私人信息留受控引用。凭证、敏感配置和音频原件不进入任务日志。

身份与运行环境配置只提交脱敏模板和示例值，禁止真实密码、令牌、私钥、登录态、含凭证URL及敏感机器配置；媒体同时核隐私敏感元数据、素材使用许可与公开范围，不能只检查画面或文件名。

发现秘密误传先停止传播，交有权责任人优先撤销／轮换仍有效凭证，再评估历史、缓存及副本处置；删除当前文件不证明泄露已消除。不得擅自改权限、重写Git历史或删除用户文件。

单文件10 MiB、一批媒体归档变更合计50 MiB仅是项目可评估的软阈值建议，**未采用不生效，也不是平台上限**。项目在原正式入口明确适用范围、依据、例外决定者及复核条件；低于阈值仍核用途和增长，超过时沿有效授权评估合适落点，不默认拒绝、转码或购买服务。

采用批量阈值时，按同一任务一批归档变更的新增／替换媒体完整字节大小合计，不按Git diff或单次请求大小计，不拆请求规避。累计体积和变化频率在有意义的变化／复核点判断，不要求每次扫描完整历史。

## 最小索引与正式记录

沿项目已有目录和命名，以路径或索引识别用途、任务／篇章、版本与候选关系，不强制统一目录树；文件名中的“正式”不构成验收依据。沿已有产物回执或项目索引补必要事实，不另建状态库。以下是按需字段目录，已有准确引用直接复用，小改不重复填表；未知记`UNKNOWN`及影响，不适用说明理由。

```text
任务／用途；维护来源与当前写者；输入或来源版本：
资产及表示类型；原件／用途副本／预览等关系与上游引用：
本表示的格式、实际字节大小、SHA-256或逐文件清单；适用尺寸／时长／页码：
原件保管人、所属执行器、准确位置、持久性；恢复入口与证据／缺口：
目标仓库＋路径＋准确提交，或原生工件引用；访问范围及授权依据：
写入与实际回读证据；检查／恢复／复建覆盖、未验及下一责任人：
采用、正式用途或验收摘要（需要时）：正式决定／验收引用及观察时间：
```

可由Git直接取得的版本不重复手填；外部回执引用准确提交，索引不反复把自身所在提交SHA写回自身。原件、用途副本和相应hash分别定位，LFS指针不冒充原件字节。索引只记录资产及副本事实；候选上传、归档完成或副本可读不使其成为正式成果，也不推动任务关闭。采用、正式用途与验收以原正式决定为准，摘要只带引用和观察时间，不能在索引维护第二套状态。

## 写后回读与增量复验

写入前沿当前任务核目标、当前写者、精确基准、本批范围、已有资产及未决上传；同内容且满足用途与访问要求时优先复用已有资产。写后保留工具原生结果与准确目标提交／工件引用，再按要求从目标实际读取。链接存在、上传成功、网页预览或LFS指针只能证明对应事实；需要原件时必须取得实际原字节及所需表示，核大小／hash。无法取得就记未验，不能称原件已交付。

摘要不一致时保留原件与预期摘要，核对象、版本、表示和传输差异，不能修改预期hash迎合结果或覆盖原件。

复用仍有效的批次授权和经差异核对未受影响的同表示内容QA，只补发生变化的传输、接收方访问、内容或呈现检查。下载完整性、目标访问、预览、播放和质量分别取证；新目标访问不从旧目标推定，转码等新表示需核受影响内容／呈现。手机播放仅在任务约定为必验时必验；既有必验项不能因已归档而跳过。检查方法和最终验收沿[产物就地复核](execution-and-review.md#产物就地复核)及[统一回执](context-and-reporting.md#产物复核与验收回执)，不重复全套QA。

部分成功或`UNKNOWN`沿原请求、提交／工件和当前写者先对账；保留成功项、准确提交及未完成范围，只补已确认缺失且获准的部分，不重放整批或另建执行。回填失败补原记录，不抹掉原生成功；未知仍留原记录承接。归档、取得、检查、负责人验收及最终交付分别报告。
