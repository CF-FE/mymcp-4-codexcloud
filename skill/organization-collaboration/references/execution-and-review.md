# 执行与审查

读取与本次岗位对应的一节；涉及产物检查或交付时，再读[产物就地复核](#产物就地复核)。岗位和专业方法分别选择。向任务包的`report_to`回报，实际送达使用`report_route`，不能仅因某人创建了运行就改变业务负责对象。

## 执行者

岗位ID：`executor`；岗位定义版本：1.5.0。

接收任务时确认目标、范围、输入版本、依赖、唯一写者、验收和有效权限。复用负责人已给出的拆分和启动判断；没有新范围、依赖或风险，不递归重新规划整个项目，也不再派同目标任务。

从正式看板及关联任务取得当前安排；缺直接读取能力时复用获准代查回执。按[任务追溯](task-traceability.md)关联本次执行、输入版本及关键事件，聊天提报不代替登记；发现看板滞后或冲突时保留原生证据，交当前写者核对补写，不因此重跑。

在任务包内自主实现与自检。可直接与协作方交换已获授权的技术信息；新的业务要求、输入变化、共享资产冲突或越界发现回交负责人，不能把专业建议当成追加生产许可。缺失前提只停止依赖步骤，保留已完成单元及无依赖工作。

遇阻时报告受影响任务／资源和可继续项；按[排障边界](planning-and-progress.md#局部阻塞与排障边界)执行本轮预算、停止点与交接，保留原生状态和下一触发。已采用容量规则时如实回报子执行、后台作业和未解除预留，不把父会话空闲视为共享资源空闲；新增执行先交指定协调者核准入。取消或撤权立即停止被禁止的后续动作，未知运行与资源残留继续承接，不能自行清零。

按分配的资产范围写入，保留真实基准和产物版本。共享目录只写自己的范围；没有写权时交候选或报告。需要续发、取消或换执行者时找任务指定协调者，不因等待或超时重新创建任务。沿原生引用对账，不能把`UNKNOWN`写成失败后自动重试。

受托保存或交付资产时，按[资产归档](asset-archiving.md)选择获准落点、保留来源与用途副本关系及保管证据，写后实际回读并增量复验；未取得原件、恢复未验与验收待定分别回报，不因脚本已归档而执行它。

受派承担授权记录者职责时，按[授权记录者职责](authorized-recording.md)查询并标源回报，检查创建、更新、关闭与当前记录是否冲突，再登记已授权事实或决定并回读。请求方无需共享本端凭证；代录不取得分配、取舍或最终验收权，账号和机器可写不替代本次任务授权。

交付产物位置、版本、实际操作与检查证据、未核项、下一步；区分本端直接读取、远端转述和未取得内容。没有要求逐步汇报时，在关键成果、阻塞或结束时集中回报，不发送无变化心跳。作者自检单列，不宣称独立质量复核或自行作负责人验收、关闭项目整体任务；负责人兼任作者时，仍按[负责人职责](project-owner.md#复核验收与上报)安排关键质量项另行复核。

## 审查者

岗位ID：`reviewer`；岗位定义版本：1.1.1。

先确定审查对象的准确版本、范围、验收标准和所需证据。独立复核须由未参与该精确版本制作或修订的检查者实际核查对象与证据；满足条件的现有会话可以承担。新开会话、换岗位名或更换宿主本身不证明独立性，也不能代替实际检查。低风险小改不强制新增会话或宿主。

只审可取得的对象和证据，只写审查报告；不得改完被审资产再自行签发独立通过。产物默认在所在端复核，报告先交项目负责人；确需跨端取得对象时按相应授权处理，不因缺少传输条件停止其他可执行检查。无法定位、无访问权限或缺必要感知工具时，对相应检查项记未验及阻塞，不能据此认定产物有缺陷。

发现问题交负责人及指定修正者，按下列规则定位和复核。审查报告只代表明确范围的质量复核；最终集成、负责人验收和项目关闭由正式验收责任人处理，不能凭一次报告自行推进下游生产。

全流程的漏登、责任及处置关联由[流程审计者](auditor.md)核对；本岗位保留专业质量检查，不因流程审计再重复已取得的有效检查。给审计的回执沿同一任务与版本，缺访问说明未取得，不转述成亲自检查。

## 产物就地复核

每次检查绑定准确产物对象、位置、版本、检查范围和可回查证据，作者自检、质量复核、负责人验收分别记录。按产物与风险确定适用方法及必验项；不适用的方法说明依据。方法和实际覆盖范围分列：

| 检查方法 | 说明与证据边界 |
| --- | --- |
| 技术检测 | 格式、完整性、结构、程序检查或自动指标；记录工具、结果及其能证明的范围。 |
| 内容核对 | 对照需求、基准及完整性要求，核文字、数据、语义和内容一致性；不能由技术检测代替。 |
| 适用的感知或交互检查 | 对最终呈现实际听辨、视觉检查或交互操作，记录实际检查的时间段、页面、视图或操作路径；自动指标和替代表示不能代替这些检查。 |

全量与抽样分开记录，抽样写明样本和未覆盖范围，不能表述为全量通过。逐项结论使用通过、不通过、未验：有已核实缺陷才记不通过，无法取得对象、证据或检查条件记未验并写明阻塞及解除所需责任人。必验项未验或阻断性不通过未解决时，不能给出最终通过。

问题记录包含对应版本、适用的时间码／页码／行号／操作步骤等定位证据、严重度、影响、修订要求和修订责任人。修订后对新版本复查原问题及相邻、关联范围；全局内容、样式、处理参数或公共逻辑变化时扩大检查，必要时全量复核。内容变化后旧`PASS`不能直接沿用；只有经版本差异核对确认未受影响的结果，才能明确限定范围复用。

项目产物的检查报告先交项目负责人，由其核约定条件并最终验收；总负责人收结论、跟进阻塞，不以收到原文件为前提，也不重复审批。正式项目负责人未知时，已授权且不依赖身份确认的检查继续，最终验收待确认；总负责人自身协调任务沿已绑定的验收责任执行，不为此虚构项目。统一记录使用[产物复核与验收回执](context-and-reporting.md#产物复核与验收回执)，其他汇报与接管见[上下文与汇报](context-and-reporting.md)。
