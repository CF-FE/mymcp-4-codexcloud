# 任务、项目事件与追溯

在已有正式记录中补齐关联，不新建竞争队列、事件数据库或自动派发器。模板是按需字段目录，已存在的准确记录直接引用；普通工具调用和任务内实现步骤不逐条建单。

## 看板优先与事实来源

各岗位接单、跟进、交接、规划下一步前，先读取项目正式看板及其关联任务、当前版本和有效回执；准确引用直接读取，复用仍有效的上下文，不每次全量扫描。看板作为统一索引呈现任务、负责人、阶段、阻塞、下一步及验收／审计链接，按需展开任务正文和原生证据，不把所有信息抄进字段。尚未切换的项目继续以原正式入口为准。聊天、转发和口头“完成”是待核对的提报，不能另建一套当前状态或直接覆盖正式记录。

统一入口不要求全员持有直接凭证。缺本次读取能力时，可沿既有授权通道由记录者[代查并标源回传](authorized-recording.md#查询与证据回传)，注明对象、观察时间、字段及覆盖；不把同机或别人的读取成功当作自己已取得。

看板优先是统一工作入口，不是让旧字段覆盖事实。看板缺项、滞后或与原生证据冲突时，保留当前值与新提报，标明待核对／待补写及观察时间，由对应责任人定向核源、当前写者补写并回读；只暂停依赖该冲突的新派发、放行或验收。已经发生的执行、撤权或有效验收证据不因登记失败而消失；权限撤销和公子新指令仍立即约束相关动作。

| 信息 | 唯一正式来源及其他位置的用法 |
| --- | --- |
| 项目目标、范围、负责人、主看板、里程碑与重要决定 | 项目正式记录；看板总览引用，不复制完整组织名单 |
| 任务身份、需求与授权来源、输入、分工和验收约定 | 任务正文及生效变更；父任务、看板条目引用同一任务 |
| 当前协作阶段、下一责任人和计划 | 正式看板／进度入口，关联对应事实或决定；登记未完成明确标记 |
| 实际执行状态 | 原生执行系统及带观察时间的回执；看板中的摘要不冒充新查询 |
| 检查与最终验收 | 检查者和正式负责人各自绑定版本的回执，按[就地复核](execution-and-review.md#产物就地复核)处理 |
| 变化过程及产物索引 | 原任务的事件时间线和受控证据引用；原件、完整日志留原系统 |

有效依据按对象、任务约定版本和决定范围判断，不取“最后一条消息”或最大时间戳。协作阶段、原生运行、记录同步和检查结论分别表达，不能用一个“完成”覆盖它们。

## 三层记录与唯一关联

项目记录至少能定位目标／范围、负责人及其任命依据、正式看板与任务保存位置、适用里程碑、关键决定和整体风险／遗留。项目重要事件包括范围、负责人、关键输入版本、环境、授权和关键决策变化；记录影响范围及关联任务，未受影响成果继续复用。

任务使用已有唯一ID或准确引用；需要独立分配、交付、阻塞或验收的成果才单独建任务。每次独立委派均有可定位记录，即使只在父任务中保留子项，也要有稳定引用、分工和执行关联。任务合同复用[上下文模板](context-and-reporting.md#绑定与确认)，补充父任务、需求来源、输入版本、预期交付与验收、派发者／执行者／验收者、依赖、当前阶段及下一步；小任务可以在同一回合完成，不重复填整张表。

同一任务可关联多次有明确理由的执行或续跑；每次绑定输入版本、范围、执行会话或原生任务／回合，以及实际派发者。用来源系统和对象类型限定原生ID，不能把显示名称当唯一身份；本地派发关联号只用于对账，不代表服务端幂等。

事件复用原生评论、回执或受控记录引用作为标识。没有原生标识时才在原任务内给稳定关联号，不另建全局编号服务。事件与任务、执行轮次及对应输入／产物版本关联；事实、决定、提报和更正分别标明。

```text
事件引用；项目／任务／父任务；执行关联或尚未取得原生引用的派发关联：
事件类型与性质（事实／决定／待核提报／更正）；关联输入或产物版本：
发生时间及来源；观察时间（适用时）；登记时间：
实际操作者；登记者；授权或决定依据：
实际动作、结果、证据引用与实际覆盖／可访问范围：
影响、未验／UNKNOWN／待补写；下一责任人、动作和解除证据：
```

按有意义的检查点记录派发、承接、进展、阻塞、授权等待、重试、变更、交接、取消、异常、产物提交、复核、验收和遗留处理。小任务可在同一回执合并多个明确事件；不复制所有日志和聊天，不编造百分比。预计长期无进展时注明已知状态、最后观察、下一检查条件和责任人；没有约定调度就不宣称会自动巡检。

## 派发与恢复

先在当前正式入口建立或关联任务，核范围、授权、派发者、验收归属、依赖与已有执行，再保留本次派发意图并调用。随后的接收回执保存真实会话／任务／回合引用。已请求、已受理、执行中、执行完成、复核完成、负责人验收分别由相应证据支持；工具返回成功不是业务完成。

| 观察到的事实 | 继续方式 |
| --- | --- |
| 只有派发意图，且有证据尚未调用 | 核当前授权与前置后沿同一关联执行；意图存在本身不能证明已调用或未调用 |
| 是否调用或调用结果不明 | 保留`UNKNOWN`，原派发者沿原请求和可能的原生引用对账；一次空列表、查不到或超时不足以重派 |
| 已取得真实执行引用，正式登记失败 | 将原生ID、版本、动作及待补写内容保存在原获准回报／受控记录，恢复后查原对象并补写；不得重建执行任务 |
| 多项写入部分成功 | 保留成功项及各自回执，逐项对账和补未完成部分；不重放整批 |
| 迟到或矛盾回执 | 绑定原版本和轮次保留历史；不覆盖新版本状态，交对应来源责任人核实 |

必要关联尚未确认时暂停依赖它的新独立派发；例外须有明确授权和待补写关联，不默默绕过。既有执行和无依赖的已授权工作按原任务继续。记录者接管时交清未知请求、已成功部分和原生引用；冲突与写后回读复用[记录职责](authorized-recording.md#写入回读与结束)。

取消、撤权、人员或版本切换分别保留业务决定和执行端实际状态。取消记录不等于原生进程停止；撤权立即限制后续动作，但已发生的副作用与未知运行仍交原责任人对账。受影响执行、遗留或后续事项有明确承接后，按约定处置关闭，不把取消写成质量通过。

## 历史、遗留与证据访问

历史补录保留原发生／观察时间、补录时间、原始来源及缺失项；时间或身份未知如实注明，不能用登记时间伪造原发生时间。更正追加引用原事件、原因和生效范围；不覆盖掉旧结论、原版本或争议记录，也不把普通可编辑时间线宣称为不可篡改审计日志。

遗留项写清原任务、影响、处置理由、下一责任人、解除条件及后续任务／承接记录。是否另建任务仍按独立成果粒度判断；不能随着主任务关闭消失，也不能用“已转交”代替接收回执。必要承接未确认时保留待处理；风险接受保留原问题与依据，不改成技术通过。

产物索引复用[产物回执](context-and-reporting.md#产物复核与验收回执)保存精确版本、所在端、位置、大小和适用的SHA／清单；音视频时长、台本／字幕版本等按类型补充。原件默认留所在端。保存摘要和可访问的原件引用，注明谁已实际读取及范围；链接存在不等于接收端能访问，缺访问记未取得并指定补齐责任人。

写入前核目标记录本身的可见性及接收者范围；私有看板不能使公开任务变私密。任务存在性、标题、路径和链接也可能敏感；没有合适私有落点时沿已有受控入口保留，不能为入板把私有内容写入公开仓库。凭证、敏感配置和音频原件不进入任务日志。实际记录写权及回读按[授权记录者](authorized-recording.md)执行，流程审计按[审计者](auditor.md)核对。
