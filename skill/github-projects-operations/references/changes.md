# 写入、批量与对账

## 先限定变更对象

沿当前任务复用明确授权；不要每个同类操作都重新请示。若上下文采用指定写者制度，负责人作决定、当前写者实际登记；负责人兼任时可同回合完成。委派生效期间双方不能同时覆盖同一条目。新增范围、现有资源关联或共享结构变更超出授权时，先准备具体变更再补所需决定。

| 方法 | 要核对的范围与证据 |
| --- | --- |
| `create_project` | 创建看板的依据、owner、可见性预期、重复／未决创建和保留安排；返回后读取实际可见性 |
| `add_project_item` | 目标板及指定源 Issue／PR 的关联授权；先核已有成员关系与未知请求。返回项目条目 ID 后读取实际字段基线 |
| `update_project_item` | 当前条目、字段定义、当前值、拟写值和有效决定；只写授权字段 |
| `update_project_items` | 逐项范围、引用形式、基线和可独立执行性；见下文批量处理 |
| `delete_project_item` | 精确项目成员关系与删除依据；它不会删除源 Issue／PR，本体状态另核 |
| `create_project_status_update` | 正文、状态、日期及对应负责人的依据；标记 COMPLETE 不替代业务验收 |
| `create_project_view` / `update_project_view` / `delete_project_view` | 共享视图属于看板维护；条目写权不自动覆盖视图名称、筛选、布局或删除 |
| `create_iteration_field` | 字段创建属于共享结构写入；先读[迭代规则](iterations.md)，核日期及完整显式周期列表 |

当前这组方法不包含关闭／删除整个 Project、删除字段或删除状态更新；遇到这些需求先报告能力缺口，不编造方法或自动转用新接口。Issue 正文、评论、标签、分配、关闭及 PR 修改使用相应源系统工具，并分别核仓库权限与任务授权。拥有 Projects 写工具不能代替这些条件。

## 写前与写后

创建前定向检查相关对象及未决请求，不扫全组织。更新前读取目标当前值与相关版本，比较提报依据；旧报告、他人新写入或相互矛盾的验收先对账。只暂停相关覆盖，可保留收到的事实和缺项，不能替业务负责人或专业检查者改结论。

执行后用独立 get/list 回读同一对象与已写字段；回包成功是证据的一部分。删除后核准确对象已消失且必要分页已覆盖。发现有其他新变更时不恢复旧快照来“清理”。写前读／写后读不是事务锁，不承诺恰好一次写入。

正式任务的完成关闭须有对应负责人的有效验收依据；取消／重复关闭保留原因、剩余执行和后续承接。子任务结果只贡献证据，不能由子任务写者顺带关闭父任务或放行依赖。源 Issue 的关闭和 Project 阶段不是原子更新，已成功部分保留，失败部分精确登记。

## 批量与未知结果

批量只用于明确范围内、可独立处理的目标；同一对象存在先后依赖的变更串行。一次批量不扩大到其他项目或字段。数量上限以实时 schema 为准，不把工具标称上限当实测规模。

逐项检查引用、`succeeded`、`failed`、`unknown`及对应错误；总计成功不能掩盖缺少或异常的逐项结果。对受影响对象回读验证，保留成功部分。未返回期望结果、传输中断或响应未知时按原请求关联对账，不直接重发整批。

确认实际未完成后，也只有在原授权和实际方法语义允许时才能继续；新的尝试仍沿原任务记录。未知创建尤其不能凭一次空列表就重建：核筛选、分页、准确名称及已返回 ID；不能唯一判断时保留 UNKNOWN。换写者须交接原请求、未知结果和已有原生引用，停止旧写者对相同目标的并发覆盖。

## 定位错误的实际层级

| 证据 | 处理 |
| --- | --- |
| 宿主安全／审批拒绝 | 操作受阻；不能当 GitHub ACL 故障。按原授权流程处理，不换连接或工具绕过 |
| 请求发出前网络／执行环境失败 | 目标服务结果未取得；不推断 GitHub 凭证失效 |
| GitHub HTTP 403 或 `Resource not accessible by integration` | 核实际连接、目标和服务端授权；不要仅凭错误猜是哪个 scope，更不自动改权限 |
| 已关闭项目拒绝视图创建等状态错误 | 保留原对象状态；换测试对象或重开需要相应授权 |
| 参数／行为不符合预期 | 核具体方法所需字段和实际回读；迭代有已知差异，见专门参考 |

保留外层代码及底层原文。历史上 `INVALID_ARGUMENT` 包装过权限、参数和对象状态问题，不能仅凭它归类。创建过程可能已有部分副作用；失败后先核对象，不一律当零写入。

## 测试与清理

先复用有效实测证据；普通操作不需要跑完整方法矩阵。需要新测试时限定项目、源 Issue／PR、允许动作、可清理资源和允许保留项；不为凑批量数量擅自关联其他业务资源。

在原任务保存本次新建对象清单及返回 ID，只清理明确属于本轮且获准删除的对象。预先确认工具不支持的清理动作及保留安排，不承诺“全清理”。仅添加关联也可能产生源对象时间线／通知；未核查时不声称无任何附带影响。

结果以实际预期区分通过、不符合预期、审批／权限受阻、基础设施中断、未验；执行结果不明另保留 UNKNOWN。报告成功部分、具体失败、未验和遗留对象。一次方法成功不覆盖该方法失败的另一分支；只有约定条件真实满足且有通信授权时才通知，原任务已授权的常规报告不另加审批。
