# GitHub Projects 操作

技能版本：1.0.1。

使用当前宿主实际提供的 `projects_list`、`projects_get`、`projects_write`；参数以当次工具 schema 为准。技能不提供凭证或安装服务。工具未暴露时准确报告加载缺口；其他会话成功不代表本会话可调用。

复用本会话已读取的明确技能版本和有效连接证据；只有版本、绑定、范围变化或实际失败时补相应检查。文件放置、实际读取、MCP调用和原生自动发现分别记录；已显式读取时可继续本次获准操作，不为自动发现未验重建会话或重跑全套接入验收。

## 最短工作路径

1. **复用目标与授权。** 从请求或有效任务上下文取 owner、owner_type、Project 编号和准确对象引用；已知是组织则显式传 `owner_type: org`。读取者在既定范围内直接 list/read，不必经记录者中转，也不逐次重新申请有效授权。
2. **按目标读取。** 有准确引用直接 get，只有目标不明或确需集合才 list。查条目进度显式请求所需 `field_names` 或 `fields`，二者不同时传。分页与筛选限定结论；未返回字段不等于空值，读取失败不等于对象不存在。
3. **写前核职责与当前值。** 写入须有对应对象、动作和有效依据；组织任务复用已有负责人决定、当前写者及委派范围。技能不任命写者，不替负责人验收。常规事实按预授权更新；缺决定或范围不明只暂停相关写入。所有外部变更，包括评论、关联和共享视图，均属于写入。
4. **执行最小变更并回读。** 保存实际返回标识；同一对象的依赖更新串行。查询回执注明必要来源、观察时间和覆盖；写入回执保留原任务、依据、目标、写前／拟写／读回值及未完成项。小查询用短结果，不强制填写整张报告。

## 按需参考

- 查询、字段选择、分页、标识区别：[查询与字段](references/query.md)。
- 创建／更新／删除、批量、冲突、拒绝、未知结果和测试清理：[写入与对账](references/changes.md)。实际写入前读取；普通只读不加载。
- 创建或使用迭代周期：[迭代与已知行为](references/iterations.md)。省略周期列表的历史异常、显式生成与回读单独处理。

组织协作规则由当前任务提供；已安装 `organization-collaboration` 时复用其权责与验收约定。本技能可独立使用，不要求另一技能存在，不把特定组织、机器、岗位名称或历史测试授权写成全局默认。

## 完成边界

判断实际对象和字段是否达到本次预期，不能只看工具调用未报错。批量逐项区分成功、失败和 `UNKNOWN`；结果未知先按原引用对账，不重放整批或重建。不得通过换连接、换代理或扩大权限绕过拒绝。

Project 的阶段、Issue／PR 本体状态和执行系统状态分别保留。关联条目不授予修改源 Issue／PR 的权限；Project 标记 Done 不证明产物已验收或原生进程已停止。只在有明确通知授权且约定条件真实满足时回报给指定接收者，未验或阻断不改写成通过。
