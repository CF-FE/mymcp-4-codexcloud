# 诊断和恢复

初始化和任务开始前按[用途预检](setup-cloud.md#初始化与任务前预检)选正式入口，复用有效回执；命令参数查当前`--help`及所需子帮助。异常发生时先定位控制端程序/IPC、API/Streams、目标执行、提议待Save或保存回读中的哪一层，再做下表的必要检查，不反复重跑doctor。需要doctor时用当前分发README的入口，保留profile、退出码与脱敏失败类别；默认不安装、不登录、不启停或改配置。结构化stdout与stderr分别读取。

| 现象 | 下一项有意义的检查 | 不应自动进行的操作 |
| --- | --- | --- |
| 无CLI或CLI版本提示 | 无CLI查稳定入口、receipt.node_path、Node engines及安装器；版本差异/未知只warn，先查实际help再继续；安装准备才按已授权latest策略更新 | 把版本差异当业务硬门槛，或由检查warn隐式触发升级 |
| 原生模块加载失败 | 明确包、ABI、平台、构建策略与下载目的地 | 关闭校验或对全部依赖放开脚本 |
| `LODY_CLI_TOKEN` 缺失 | 仅检查注入状态和当前任务配置 | 输出整个环境、请求聊天重交 token |
| 变量存在但未登录 | 核实已有合法私密身份；显式认证另核授权副作用。0.108.1仍无已核实的LODY_CLI_TOKEN直读/无状态目录flag | 把占位符写入登录态、默认登录/配对/设备授权，或自造目录认证SDK |
| auth 缺状态目录或目录不安全 | 指定当前用户拥有的 `0700` 非符号链接目录；只在任务内准备身份状态 | 把登录态放进安装依赖目录或共享快照 |
| doctor 的 control/task/worker 被阻塞 | control 需显式 `--connect` 与已有私密状态；执行需独立真实证据 | 自动登录、启动 Agent，或把查询通过当任务能力通过 |
| 目录退出0但syncing/页未完整 | 核对sync.state、新鲜度与cursor/hasMore终止条件；只在授权范围后续核对 | 把未同步的空items或第一页当完整空目录 |
| 目录原始exit0但整段JSON解析失败 | 核对0.107.2是否仅夹带同workspace的Streams attach/detach诊断；使用随包工具的窄兼容并继续校验完整分页 | 任意截取最后一行、忽略未知日志、把失败当空目录 |
| workspace list 成功但机器/Role 查询超时 | 用明确 workspace 运行目录诊断；当前部署另需 Loro Streams 分片后缀，检查 CONNECT 403 与实际 hostname | 报告空资源、把登录成功当全部网络通过 |
| workspace/资源访问失败 | 实际身份、明确 ID、已有权限与选择器 | 静默换工作区、换身份或扩权 |
| Role提议报`DAEMON_NOT_RUNNING` | 核命令实际所在端及本机IPC前提；按[配置](configuration.md#role-的两种使用)选已授权正式入口 | 归因目标离线/CLI未装/用户未Save，或靠`--session`假定已转远端 |
| 所需daemon/IPC未就绪 | 核已有进程、版本及实际恢复/启动的登记与订阅范围；已有授权普通进程恢复与新host分别判断 | 自动注册完整host探活，或一概禁止未扩权的合法恢复 |
| Codex ACP initialize 报 SQLite/read-only | 核实确切运行版本、官方状态目录设置及宿主写入边界；单独 SQLite 目录不能保证 CODEX_HOME 的其余状态可写 | 改 HOME/CODEX_HOME、复制认证或反复猜参数绕过托管限制 |
| 网络 403 | 保留CLI原始退出码、操作、准确目标hostname、HTTP状态与响应来源；分清代理CONNECT、API与Streams层 | 绕过代理、关闭TLS、回传原始debug/响应正文，或仅据403断定workspace无权限 |
| 连接或观察中断 | 按[主动恢复](#断连后的主动恢复)检查实际连接、执行器、原生任务及审批等待，沿原获准入口恢复并对账 | 把断连等同任务停止，重放结果未知的业务请求，或用新任务探活 |
| 任务比预期慢或进度空页 | 查审批/授权门及原引用的执行状态、同步/分页覆盖与长调用；空页有后续游标则有界续读，见[会话](sessions.md#观察真实结果) | 未观测就断言未发生，反复报进行中或催促重创 |
| 等待权限确认 | 核对具体 tool、必要参数、目标、风险和 requestID；当前入口读不到时明确说明并指向原会话受信任界面 | 承诺 CLI 能读工具详情/approve，拼内部 RPC，选全放行/always，发 yes 或改 mode 绕过 |
| 创建/聊天请求超时 | 已返回标识、operation、持久化会话状态和历史 | 未核实前重新创建或发送新消息 |
| 长对话或单session达到轮次上限 | 区分单session与workspace总额及实际拒绝；按[摘要交接与接续](sessions.md#长会话接续与额度单位)核旧执行、成果保全、当前新建准入及新端承接，再按授权归档旧会话 | 继续append满额会话、把单会话限制误判为禁止同任务接续，或用归档／换身份／换工作区规避真实额度和安全拒绝 |
| 聊天退出1但未得ack | 保留脱敏异常原文与退出码，核完整可见历史、队列和latest/handled turn；缺服务端受理证据时保持unknown | 只凭兜底分类猜权限，或仅凭最近若干条未见消息就改为未执行并重发 |
| Role同名或pending卡需要新版内容 | 核原Role是否已保存、原卡/requestId与版本；已保存同ID更新，pending由用户在受信UI处理 | 用同requestId改内容，或换ID再建同名卡制造重复 |
| 用户说已授权或最新回合已变化 | 立即重查原会话；按原 userTurnId/assistantTurnId 对账，必要时匹配原助手 history 条目的 text | 重发原任务、用最新新回合代替原结果，或擅自取消用户后续工作 |
| Role 或 schedule 响应成功但未变化 | 是否只是确认提议、是否已由用户保存 | 自动当作配置已生效 |
| CLI 更新但行为仍旧 | 稳定 launcher、运行中 daemon/watchdog 的真实版本 | 把 npm 安装成功当运行版本已切换 |
| 未知参数或资料冲突 | 当前准确命令 `--help`、兼容版本与来源 | 猜参数、用内部接口绕过 |

原连接或观察可按下节有界重连，不要求每次已有新的根因结论；业务写入及派发的未知结果仍先对账。观察任务时选持续观察或适当快照，不建立无意义高频轮询。来源配置版本号不变本身不能证明当前网络规则未更新，应检查实际生效规则及请求结果。

`0.108.1`公开状态/历史不提供待批工具详情或一次性approve入口。具体边界、授权等待与原回合对账按[会话任务闭环](sessions.md#慢任务与授权确认)处理；不以内部schema冒充公开能力，版本变化时定向复核。

## 断连后的主动恢复

1. **先分清断在哪一层。** 沿当前任务核本端执行器能否实际执行、连接／观察通道、原生任务状态及审批等待；无法取得的状态保留未知。网络抖动只是可能原因，观察断开不表示业务停止，消息被接收也不证明执行器已经恢复。
2. **主动恢复原获准入口。** 在已有明确授权及范围内，使用原连接和宿主实际支持的重连／恢复方式，不逐次重复询问。范围未变的已获准普通进程恢复按实际副作用判断；不自动注册新host、复制身份、扩权或绕过拒绝。不猜通用重连命令。设定尝试次数或时间预算，按实际错误合理退避，避免热循环；权限／审批拒绝不按网络抖动反复尝试。
3. **恢复后补齐进度观察。** 按原任务、原生请求／会话／回合及输入版本核最后观察、同步与分页覆盖、产物和下一责任人，恢复该任务所需的观察。仍运行则继续跟进，已有终态则核对应产物；未决请求保持`UNKNOWN`先对账，不重派、不用新chat/create替代查询。
4. **同时核所需派发入口。** 复用有效回执、当前宿主入口及必要只读证据，分别报告观察、执行器可用性与派发能力；工具可见、重连成功或一次查询通过不证明业务派发已验证。缺口只影响依赖动作，不用真实任务或新消息探活。对已明确授权且条件满足的工作继续推进，恢复本身不新增生产或重派授权。
5. **有界跟进并准确报告。** 持续失败达到预算，或需要权限确认／用户步骤时，说明准确动作、目标、错误层级、已完成部分、已拒绝／待确认／未知及下一责任人。其他无依赖工作继续；按当前待办和约定检查点保持项目进度感知，无待办不无限轮询全部项目，也不反复发送无变化状态。

## 403与诊断证据

2026-10-25对Lody0.108.1官方CLI的有界复验已通过，82个观测HTTP响应均200，未出现401/403；当前不再以旧探针作为准据、待办或阻塞，也不继续其根因调查。下述只是在当时版本再次发生实际CLI失败时如何保留证据，不代表未来版本不变或本次仍有故障。

先核对发出的是官方CLI命令还是单独的健康/HTTP探针，再记录请求的目标、观察时间、CLI原始退出码及HTTP状态。代理`CONNECT 403`、Lody API拒绝、Streams网关拒绝是不同来源；只保留不含查询凭据的hostname、方法/操作和脱敏错误类别。没有足够响应证据时原因保持unknown；网站可读或探针返回成功不能替代CLI授权、完整目录同步或Agent执行。

0.108.1发布源码显示Streams provider默认在401/403触发短期token刷新并重试一次，特定带Producer-Epoch的append/appendCas 403有例外。这不是创建新的CLI API key、设备登录或无限重试；2026-10-25官方CLI复验未出现403，因此未触发其刷新重试分支；该版本也没有CLI层已核实的`refreshOn403`关闭开关。不要为诊断猜开关、改协议、重新登录或反复派发业务请求。完整来源及符号集中在[来源记录](sources.json)。

源码支持的request ID与`cf-ray`仅经过格式过滤，不能据此认定内容已脱敏；诊断投影还可能含workspace/room，原始异常可拼接响应正文。不要直接回传完整`--debug`、原始异常、响应body/header或带签名URL。按具体故障提取必要字段并人工检查敏感内容；ID仅用于已授权渠道内的关联。Undici诊断开关也不是账户权限检测或独立原生doctor命令。

需要日志时只取与故障相关的脱敏片段，不输出 token、完整环境、带签名 URL 或私密配置。恢复不删除用户已有登录态、daemon、项目或会话；仅撤销本任务拥有的测试配置与临时进程。

成功报告需说明修正了哪个具体前提、哪个受影响检查随后通过，以及仍未运行的能力。缺少底层 Agent 凭证、宿主加载或真实测试目标时，只阻塞对应能力，继续可以独立完成的资料与本地检查。
