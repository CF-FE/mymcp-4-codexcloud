# FileKiwi 文件中转与接收验收

这是获准跨环境传文件时的操作参考，不新增服务、下载API或自动授权。FileKiwi API事实核对于2026-10-26；容量、保留期、费用、工具版本与可用接口每次查当时官方说明。一次性验收记录另见仓库验证文档，不把历史通过当作当前环境已接收。

## 先确认范围与实际执行器

- 明确素材、发送端、接收端、原文件绝对路径、目标目录及允许的写入方式。测试合成文件的授权不包含把真实项目资料上传第三方；第三方上传、向外部Agent交付含密钥链接分别核对本次授权。
- FileKiwi负责获准的中转，Library负责用户交付、保存或回传验收文件。Library对象存在、分享链接生成、发送端本地路径均不能证明接收端取得字节。
- Library原件按当前Library技能的正式materialize流程取得，完整转交返回的transfer及headers给官方helper；不能给外部Agent一个私有下载URL当作通用直链，也不把producer路径当consumer路径。
- 使用来源已核验且获准的客户端，记录当次版本。工具未安装时先报告前提；本页不是安装新软件、启动Agent、创建身份或修改网络/安全设置的授权。
- 分享链接的fragment含解密秘密，只交给获准接收端并在官网解密；不得进入仓库、普通报告、常规日志、截图、trace或HAR。上传认证、签名URL同样保护，公开清单不保存这些值。

## 每次传递的最小记录

复用任务的私密记录，不另造通用schema，也不写入公开仓库：

```text
任务/时间与客户端版本：
授权素材范围：
发送执行器 + 原文件绝对路径：
接收执行器 + 预定目录：
文件名 / 字节数 / SHA-256 / ZIP成员与CRC（如适用）：
原上传任务标识与脱敏证据：
独立最终上传状态：HTTP / complete / missing：
接收端实际文件绝对路径：
接收端字节数 / SHA-256 / ZIP成员与CRC：
Lody session/user/assistant turn（如使用）：
目标导入、目的地回读、Library保存（按请求分别记录）：
各阶段状态、失败来源、仍缺信息：
```

预定目录和实际落盘路径分开；没有取得字节的阶段，长度和摘要保持未知。

## 标准步骤

1. **准备源文件。** 在发送执行器确认文件存在，生成名称、字节数、SHA-256清单；ZIP检查成员路径与CRC，避免带入秘密、无关文件或链接密钥。校验ZIP不需要执行其内容。
2. **上传并保留原任务。** 按当前已核客户端/API加密上传，保留真实任务标识、版本、退出状态。MCP即时返回链接或CLI退出0，不单独等于上传完成。保持后台上传与其原任务关联，不再建一份同样上传。
3. **独立核最终状态。** 对创建时已注册文件的API上传，按实际版本使用公开状态接口；v2为`GET /v2/folders/{folderId}/files/{fileId}/upload-status`，v1为`GET /v1/upload/check/{fid}`，参数来自真实回执。检查HTTP成功及正文`complete: true`、`missing: []`，不能只检查SDK调用返回。v2空目录后网页上传是另一契约，没有同样的初始文件注册/状态前提，不能混套。缺块或结果未知时先对账原任务，保留证据后恢复缺失步骤。
4. **接收端浏览器下载。** 先核当地已暴露的自动化工具、可正常启动且启用安全沙箱的浏览器、磁盘目录及本次权限。到实际接收环境打开获准完整链接，按官网流程解密并保存到不覆盖已有文件的独立目录。工具缺失、沙箱/权限失败或第三方安全确认时先报告具体步骤；不禁沙箱、不关闭证书检查、不猜下载API，也不把上传PUT改GET。
5. **核实际落盘。** 页面完成、进度100%、download事件或事件超时，都不能单独判成功/服务故障。先检查原下载任务、权限/保存确认、工具约定的下载目录及本次拥有的临时文件；不扫描无关用户目录，不清理已有浏览器状态。只有读取到实际文件，才比较源清单的大小和SHA-256，并检查ZIP成员/CRC。超时且文件未知时，不直接重复点击、另建上传或换接口。
6. **交付及目标验收。** 需要Lody时再用正式`session create/chat --attach`交付控制端真实本地附件，明确机器、项目、配置与授权；创建超时先对账，见[会话工作流](sessions.md)。附件缓存不等于已导入项目，也不自动解ZIP。目标导入前核已有内容和冲突，不覆盖原件，导入后回读文件清单/摘要及必要引用。Library保存与目的地回读分别核验；各项成功不能互相替代。

使用Lody前先查当前版本帮助。0.108.1的附件从运行CLI的机器读取；没有控制端真实文件时，不能用URL或另一执行器路径冒充`--attach`输入。目标Agent若实际提供正式附件回传工具，可在授权范围只回传测试文件；CLI可见文本收据仍是Agent自报。小型无敏感测试件可获准用正文base64回传，控制端严格解码后独立比较字节长度/SHA/CRC；这仍不等于控制端直接读取了远端文件系统。不得为取ZIP导出整个工作区或调用内部项目RPC。

| 阶段 | 通过证据 | 不足以通过 |
| --- | --- | --- |
| 源准备 | 原执行器路径、实际字节数/SHA、ZIP成员/CRC | 计划名称或另一端路径 |
| API上传最终完成 | 原任务的独立HTTP成功及complete=true、missing=[] | 分享链接、即时回执或退出0 |
| 接收落盘 | 实际接收执行器可读文件和绝对路径 | 页面提示、事件或事件超时 |
| 内容一致 | 接收文件大小/SHA与源一致，ZIP成员/CRC通过 | 只有名称或大小相同 |
| 自动接收通过 | 自动操作落盘且内容校验通过 | 用户手工下载再回传通过 |
| 目标初始化 | 指定目标导入及所需文件/引用回读 | 附件已上传或Agent仅说已完成 |

## 慢任务、确认门和未知结果

比预期慢或无输出时，第一步检查原调用/session/user turn是否等待授权，再查进程、网络或文件进度。出现waiting立即向用户说明实际动作、目标、待确认内容及所需入口；工具读不到具体项时明确这一限制并指向原会话受信任界面，不能猜参数或只说“处理中”。用户表示已授权后立即重读原会话，核对原回合结果及后续回合标识，持续负责到验收、明确失败或真正需要用户输入的边界。详细规则及0.108.1公开接口限制见[会话观察](sessions.md#观察真实结果)。

批准不是执行成功，等待不是完成；不自动allow-all/always，不发“yes”或改权限模式代替确认。结果未知先查询原任务和文件，不盲重试上传、创建、覆盖、删除或初始化。拒绝后保留动作、目标、状态与原因；只在明确未执行且有实质新证据时按任务允许范围重试，不换身份或接口绕过。

## 官方契约与版本范围

- [公开v2 API](https://file.kiwi/api)、[v1 API](https://file.kiwi/api/v1)、[OpenAPI](https://api.file.kiwi/openapi.json)：本次检视只公开创建/上传状态相关接口，未发现公开下载API。不能将内部对象路径、上传URL或SDK上传能力当作已文档化下载能力；将来变化时重新核验。
- [官方故障说明](https://docs.file.kiwi/en/troubleshooting/)：分块合并可能使下载未保存，保存位置取决于实际浏览器配置。此说明不是对当前某次失败的根因证明，也不授权删除浏览器缓存、切换环境或修改设置。
- 本轮检视的工具`@file-kiwi/filekiwi-mcp-server`为2.0.1、所用SDK为1.0.9；观察到上传可能先返回链接，完成通知未校验HTTP响应，所以保留上面的独立最终状态检查。该观察限定这些版本与本轮源码审阅，不作为未来SDK的永久缺陷判断，也不证明本插件已安装这些工具。
