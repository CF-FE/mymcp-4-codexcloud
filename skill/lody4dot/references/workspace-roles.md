# 工作区共享角色与项目协作

角色定义说明职责，不能替代实际工具、权限、用户任务或运行证据。先按[配置与角色](configuration.md)核当前命令与保存方式，再选择明确工作区、机器、配置及项目；本文不授权创建、派发或生产。

## 区分共享职责和项目责任

角色定义分工作区共享级与项目级：共享级维护跨项目职责、方法和交付约定；项目级维护项目负责人、领域职责及项目特有输入和验收。项目按需引用共享职责，不复制其全部规则，也不自动取得共享角色或其他项目的写权限。此处是角色库的组织层级，不假设Lody已有Project→Role持久绑定接口；实际machine/config/Role、Save与字段回读继续单独记录。

可采用一个协调入口、六项按需共享职责和一个项目负责人的布局：视觉设计、研究分析、质量审查、运行工程、知识管理、辩证复核。完整定义应按用户已接受版本读取，不从岗位名临时猜提示词。项目规划、编剧表演、音频字幕等可作为按任务加载的职责模板，定义数量不等于常驻Agent数量。

- 协调者负责跨项目优先级、用户沟通与授权边界；项目负责人负责正式入口、CURRENT/状态、授权映射及冻结清单，不能建立竞争状态库。
- 共享角色默认交候选或报告。其他资产可以明确委托单一阶段写者；记录路径、输入版本/hash、范围和交还条件，切换前确认旧写者停止，合并前核基线未漂移。跨机器位置不是远程正式写权限。
- 研究提供证据而不接管项目事实主库；知识提供索引候选而不裁定完成状态；运行工程诊断工具链，不兼任常规媒体作者；视觉自检不算独立QA。
- 辩证复核检验方案前提、最强反例和可行替代，交更优可执行方案、取舍与验证/停止条件；QA检验精确版本的实物是否满足已接受标准。小任务不默认增加复核门，两者都不代替项目负责人决策。

本方案的辩证岗位采用一岗双方向：同版输入/hash、范围与证据权限分别交给实际独立上下文，A对抗线找未证前提、最强反例和失败路径，B优化线保留有效部分并比较可执行替代。首稿完成前互不读取对方结论，随后按主张对齐共同事实、证据强弱与取舍，交一份可决策方案；证据不足的分歧保留给owner，不强行一致。只有同一上下文时标双视角自审，不能冒称独立；不新增两个常驻角色，也不在仅保存配置时启动任何路线。

具体机器名称属于当次映射。重命名后按稳定machine ID核项目和会话，当前方案使用新名称，历史审计保留旧名及别名；不重复执行重命名。某台机器上的模型或工具不自动成为另一台机器的fallback。

## 版本化接收与发布

1. 核源文件完整字节及SHA；分段文本仅按序解码拼接，截断、缺段或摘要不匹配时不补写定义。中立设计JSON不能直接传给CLI严格schema。
2. 把协调定义、项目owner、任务模板与真正共享Role分开，只对用户明确要求的Role发布。每项映射真实`name/description/promptPrefix/machineId/agentConfigId`，先核长度和当前schema；不猜`team/project/inactive`字段。
3. 核同名已保存Role和已有提议。已保存用同ID更新，pending/unknown按[提议幂等规则](configuration.md#project-与-role-的组合)处理；新版本ID不构成重发未知写入的理由。无正式控制入口时不要拼内部RPC或启动host。
4. 若借用已有Agent会话发布卡，先核该命名接收者与用途的授权、会话真实目标及活动回合；不因为能chat就把新消息当直接工具调用。仅发布卡不等于启动角色，也不等于授予任务执行、软件安装或模型下载。
5. 模型与强度可以记录为建议。用户接受默认时保存平台支持的默认配置，明确尚未人工设置；不为实现建议阻断无依赖工作，不静默换模型、机器或凭据。
6. 保留卡/request/Role ID和对应session/user/assistant turn，报告pending与用户Save位置；保存后按正式list/get回读字段与提示词摘要。设计源的状态不伪改成部署成功，部署回执单独记录。

角色提示词不得把某次历史批准固化为常设权限：清理、删除和其他有副作用的操作须核对当前任务的有效授权、对象及可恢复性；角色提示词、旧记录或历史批准不构成新的许可。保护源素材和已验收成品，不凭本角色定义扩大权限。

## 交接与证据

任务至少写明授权范围、输入版本/hash与最小读取材料、输出与验收、唯一写者/接收者、预算和终点。最小材料不能裁掉全文或完整音轨验收必需范围，不默认双机全库同步或跨项目复用私有资料。

独立QA须使用未参与被审对象制作/修订的上下文，不靠角色改名证明独立；实际查看、全文语义、听证、ASR、技术检查、保存回读和发送分别取证。来源目录可读、角色已保存、技能已放置均不代表工具加载、模型可运行或生产已获准。缺证只阻断依赖动作，继续可以独立完成的授权工作。

仓库的版本化设计源与部署记录见[工作区角色资料](https://github.com/CF-FE/mymcp-4-codexcloud/blob/main/docs/lody4dot/workspace-roles/README.md)。它是已接受设计和实际落地状态的分项记录，不把某个项目规则推广给全部工作区。
