# 同步、导出、迁移与评审

适用于 Lody `0.107.2` 的导航与已核实行为。这些命令不共享一个统一的副作用模型；先查具体帮助，再选择任务流程。

2026-10-25已重新递归核对0.108.1全公开帮助，并对本节关键handler做静态source_verified复核，见[逐项审查](command-audit.json)。以下旧版本业务记录不改称新版线上通过；本轮未执行同步、导出、迁移、反馈或桌面动作。

资料空间交接、Dot中转或把结果存回指定对象，先读[资料交接](material-handoff.md)，分别报告处理、保存和目的地回读；不把这里的Lody同步或导出命令当作通用资料上传入口。

| 命令域 | 使用前核对 |
| --- | --- |
| `lody sync --help` | 同步对象、方向、身份、网络和实际完成状态；不把“同步完成”推导成代码已推送或任务已完成 |
| `lody export --help` | 源对象、范围、输出格式、输出路径以及是否包含敏感资料；不要默认覆盖已有文件 |
| `lody migrate --help` | 来源、目标工作区、支持的记录格式，以及中断恢复约定 |
| `lody review --help` | 输入格式、本地 Git 提交是否齐全、Viewer 下载和输出位置 |
| `lody feedback --help` | 当前版本支持的输入与提交范围；反馈属于外部发送，不自动上传诊断包或日志 |
| `lody app --help` | 是否存在受支持的桌面客户端；无桌面云环境不能仅凭 CLI 安装成功就声称可打开应用 |

没有核实具体参数的命令域只提供帮助导航，不拼出看似可执行的业务命令。命令成功后分别验证远端状态或本地输出，不将帮助存在标记为功能已验证。

## 同步、导出与反馈的准确范围

实际 `0.107.2` 帮助已核实：`sync` 同步工作区 Loro 数据到本地缓存，可选择一个工作区或显式选择全部；`--json` 给最终摘要，`--jsonl` 给进度及最终摘要。它不是 Git push，也不完成 Agent 工作。

```bash
lody sync --workspace WORKSPACE_ID --json
lody export --workspace WORKSPACE_ID /path/to/export-output
```

`export`输出用户可见会话数据，`--no-images`跳过图片二进制；`--offline`只跳过前置Loro同步，不能当作无网络或无授权模式。0.108.1源码中该入口仍需合法身份及workspace，默认可能下载图片，并尝试usage查询，即使不下载图片也不保证不联网。选择`--all-workspace`会扩大为全部可访问工作区，不能在只允许单个工作区时默认使用。导出前确认输出位置和隐私范围，之后核对实际文件与新鲜度。sync/export均可用独立manager，不要求已有控制端daemon；会写本地缓存或导出文件。

`feedback` 会发送账号身份和基本 CLI/OS 信息；仅在用户要求发送反馈时使用。实际帮助支持位置文本或 `--stdin`，选项放在文本之前，文本以连字符开头时用受支持的 `--` 分隔。提交前排除凭证与私密内容，不能把排查日志默认当反馈外发。

## OSS 记录迁移到 cloud

目标是把支持的 OSS 记录导入既有 cloud workspace。此流程不负责迁移项目代码目录或原生 Agent 凭证。

1. 确认迁移已获授权，指定实际源数据目录与目标 workspace，确认源 OSS 应用和 CLI 已关闭，避免迁移时继续写入。不要停止所有权不明的进程。
2. 查看当前版本 `lody migrate --help`；已记录入口为 `lody migrate --from-oss`。它会要求选择既有 workspace 并确认源/目标摘要，不自动新建 workspace。
3. 自动化时，只有在源、目标和操作已明确授权后，才使用帮助支持的 `--workspace <workspace>` 与 `--yes`；自定义源目录由支持的 `--source <directory>` 指定。
4. 读取迁移结果，验证目标工作区记录与附件；保留源目录及恢复所需状态。中断后按照当前版本恢复契约继续，不删除源记录来制造“迁移完成”。

已记录的迁移行为：导入完整 Loro 历史及其引用的本地文件附件，保留已有 cloud 会话与设置，并禁用导入会话/调度的执行。Roost 和不支持格式会在记录上传前失败；重跑恢复冻结快照。不要因此假定导入的任务已启用、已执行，或所有历史格式都受支持。

0.108.1源码还显示交互缺身份时迁移可能进入设备登录；不能把迁移当只读预检，也不能将设备创建远端key的流程混入只允许临时本地身份的许可。当前仅静态核对，没有冻结源、写journal或导入远端数据。

成功证据是目标工作区中的记录及引用附件通过核对，而不是只看到 CLI 退出码为零。权限不足、格式不支持或恢复状态冲突时，保存脱敏错误类别和源/目标选择，停止受影响操作。

## Lody Review

目标是将结构化审查文件渲染为可分享的自包含 HTML。这个流程不需要 Lody 登录、不需要 daemon，也不启动服务器；它只读解析本地 Git 仓库。

```bash
lody review prompt
lody review /path/to/report.review.md --repo /path/to/repository --no-open
```

先读取 `review prompt` 给出的当前格式说明，再按已授权审查目标编写 `.review.md`；不在此复制一份容易漂移的完整格式模板。渲染时，文件引用的提交必须已存在于本地；PR 只有远端 SHA 而未取得对应提交并不足够。

原始 `.review.md` 需要对应 Git 仓库，使用工作目录或 `--repo` 明确定位。已导出的 `.review.json`、`.review.json.gz` 或 `.review.json.br` 快照自包含，可不依赖 Git 仓库渲染。首次渲染可能下载对应版本的 Review Viewer，需保留其校验和缓存机制，不绕过完整性检查。

默认 HTML 写入系统临时目录，CLI 输出绝对路径；`--output <report.html>` 可指定路径，`--no-open` 适合无桌面云环境。核对 HTML 文件确实生成、输入对应目标提交，然后向用户报告审查源文件和 HTML 路径。渲染成功不能证明审查判断正确，也不能自动授权发布报告。

## 桌面应用与缓存

`lody app` 面向桌面客户端。云端没有受支持桌面环境时，标记该能力不适用，继续使用支持的 CLI 流程。

其0.108.1根入口有实际action：读取身份、尝试登记本机项目并打开桌面/链接，不是纯分组健康检查。`project add/delete`也需要本机control host，delete要求交互TTY；只在明确允许登记变更时使用，不为列目录启动host。

`lody app reset-cache` 记录下次桌面端启动时的清理请求；它不是立即清理完成。普通模式保留登录，`--hard` 会清除登录和本地偏好，`--cancel` 撤销未执行请求。此类修复必须符合用户当前授权，不因为排查其他 CLI 故障就自动执行。
