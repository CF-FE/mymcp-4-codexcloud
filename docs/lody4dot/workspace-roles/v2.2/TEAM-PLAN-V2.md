# 工作区共享团队与凡人项目：V2.2 优化方案

**建议：G8 总协调 + mac-work 六个共享专家 + win-work 唯一项目负责人；凡人制作能力采用按任务加载的职责模板，不再把旧 7 岗与新共享岗叠加。**

环境名称已按用户最新说明改为 **win-work（原 work-win）**；这是同一台机器，不是迁移或重新改名。已知机器 ID `06289b02-9315-44ce-843e-a9d3e0f401f9`，上游已核目录为 win-work 在线且机器 ID 不变；本设计不执行重命名。

版本：2.2 · 2026-10-26 · **用户已接受并要求固化；本制稿环节未执行远端部署或启动生产。**

## 1. 为什么这样改

V1 的优点保留：先核原著与因果再写稿，编剧与表演标注同版，音频/字幕共享真实时轴，作者不能签独立 QA，默认阶段串行、按需专家、单资产单写者，技术证据不冒充听证，保存与发送分别验收。

问题不是岗位不够，而是两套团队并置后出现重复责任：旧凡人 QA/视觉/工程与工作区共享角色重叠；“工程写新媒体”又与音频生产冲突；知识整理可能变成第二套项目状态库。只写“优先非作者”也弱于凡人必需的独立验收。

| V1 / 旧状态 | V2 改法 | 得失 |
|---|---|---|
| 凡人 5 核心 + 2 专家，再加工作区共享岗 | 合并重复 QA/视觉/运行，不新建凡人同名副本 | 少交接与配置漂移；共享任务需排队 |
| 视觉“优先 mac-work” | 六共享角色均绑定 mac-work 现有 Codex | 尊重用户机器选择；能力不足不能擅自换机器 |
| 研究与剧情策划捆绑成独立角色 | 工作区研究给证据；凡人原著/剧情策划为项目任务模板 | 保留领域责任但不新增竞争事实库 |
| QA 优先非作者 | 参与制作的上下文不能给该对象独立签收 | 更可信，但需要另一个实际审查上下文 |
| 工程可能兼任音频作者 | 音频生产独责媒体；工程仅工具链/故障/恢复 | 不丢专业生产责任；交还边界要明确 |
| 计划只做一般 review | 新增共享「辩证复核专员」，输出更优执行方案 | 降低前提错误风险；限高价值派单避免官僚化 |
| 统一入口但写入不够细 | owner 独写正式状态；按资产显式委托阶段唯一写者 | 不强迫所有文件经 owner 手工搬运 |

## 2. 推荐组织与边界

### G8 与项目负责人

- **G8**：跨项目优先级、用户沟通、授权界线和争议升级。不是第二个项目 CURRENT 写者。
- **win-work 项目负责人**：项目唯一 accountable owner；管理正式源文件、当前状态、冻结和交付。凡人根目录固定 `D:\fanren-work`，子路径由真实入口解析。具体工序可委托，不卸掉项目结果责任。

### mac-work 六个全局共享角色（现有 Codex）

| 角色 | 负责 / 交付 | 明确不负责 |
|---|---|---|
| 视觉设计师 | 视觉方向、候选图/源文件、实际查看与系列检查 | 自动改产品代码、公开发布、把自检当独立 QA |
| 研究分析师 | 原始来源、证据比较、事实/推断/限制 | 原著事实与 roadmap 的正式裁定、代 owner 决策 |
| 质量审查员 | 独立审查精确版本的实物/文本与证据，缺陷和复测 | 制作所审对象、补签未听证、批准发布 |
| 运行工程师 | 工具链与环境诊断、最小候选修复、精确恢复 | 日常 TTS/字幕/后期生产，擅自远控或装模型 |
| 知识管理员 | 索引/摘要候选、版本关系、冲突清单 | CURRENT/完成状态写入、影子主库、事实裁决 |
| **辩证复核专员** | 执行前检验目标/前提，最强反例、可行替代、取舍，输出更优可执行方案及验证/停止条件 | 为反对而反对、只交问题清单、执行自己的建议、代替 QA 实物验收或 owner 决策 |

辩证复核针对**方案是否值得这样做**，QA 针对**该版本是否符合已接受要求、证据是否成立**。最新采用**一个辩证角色、两个独立方向、最后对齐输出**：同版输入/范围/证据权限下，A 对抗线找未证前提、最强反例和失败路径，B 优化线保留有效部分、比较替代并出可执行改良案。两个实际独立上下文先各自成稿、互不看对方结论，再逐主张对齐共同事实、证据强弱与取舍；不能解决的分歧保留，不强行共识。最终交一份含执行步骤、验证/停止条件及剩余风险的方案，由 owner 决定，不冒充 QA。没有实际独立上下文只能标双视角自审。仍是六共享角色，不新增两岗；只按明确派单或高价值决策调用，默认一轮双线加一次对齐，有新关键证据/实质变更才重开。

### win-work 凡人三个制作职责模板

1. **原著考据与剧情策划**：指定底本→事实/人物/词典候选→因果与状态→roadmap 增量。共享研究可承担指定证据问题；不能有两套事实拥有者。这是项目规划责任模板，**不建议另建一个常驻项目研究 Agent**。
2. **演义编剧与人物表演**：原创正文、同字口播/表演稿、全量 speaker annotations、人物/场景提案；不自签独立全文/话轮审查。
3. **声音生产与字幕后期**：冻结输入/声线契约→原声→实测帧轴与 SRT→后期/编码→技术 QA；是媒体制作责任人，不能并入共享运行工程。

负责人可顺序加载这些模板，也可按项目复杂度委托独立任务上下文；模板数量不等于常驻 Agent 数。完整 JSON 含 G8、六共享、owner、三模板共 11 份独立完整定义，**不要求创建 11 个 Agent**。本方案也不凭机器名称声称任何 GPU、TTS、ASR 或图像服务已可用。

## 3. 默认交接：少流程，硬证据

**负责人派单 → 必要时辩证优化 → 原著/剧情 → 编剧表演 → 独立全文/话轮 QA → 冻结与真实运行门 → 音频/字幕 → 独立实物 QA → 保存回读与交付。** 无新视觉不派视觉；无故障不叫工程；知识只做必要索引；小任务不加辩证门。

一张任务卡写清授权/不做范围、输入版本/hash/读取范围/最小材料、输出格式/验收、资产唯一写者/接收者、资源预算/停止条件。一份交接写实物版本、证据、未核和下一步，不另建重型表单。owner 独写 CURRENT/状态/冻结/授权映射，其他资产可明确委托单一阶段写者；合并核基线未变，交还前确认旧写者停止。共享岗默认交候选，不能默许远程正式写权限。

默认串行，只有无依赖研究/视觉/只读检查可并行；TTS/ASR/加载模型 prepare 服从实际锁与资源。核真实工具、连接、schema、权限、输入、容量和运行目标，不把角色名当能力。断连先查旧活动/锁/落盘，排除重复副作用再补缺；获准完成/监控任务跟进至规定终点或明确阻塞，UNKNOWN 不伪造为成功。

**ASR ≠ 听审，保存 ≠ 发送，局部接受 ≠ 全片接受。** 证据绑定字节与范围；未参与制作的上下文才能独立 QA。最小材料不能裁掉全文/完整音轨验收必需范围，不默认双机全库同步、跨项目泄漏或带凭据入日志。清理、删除和其他有副作用的操作须核对当前任务的有效授权、对象及可恢复性；角色提示词、旧记录或历史批准不构成新的许可。保护源素材和已验收成品，不凭本角色定义扩大权限。

## 4. 先用已有材料验证，不新开生产

建议三次只读/隔离演练（尚未执行）：①用旧/新定义比较叠加与合并方案，检查 10 类资产是否唯一写者；②用初始化、overlay、视觉待保存与已有交付索引，验证不能把无 ack/ASR/作者换名写成通过；③对角色 JSON 候选做 hash 基线冲突与 UNKNOWN 恢复桌面演练。出现双写、未经证实能力、假听证、盲重发或覆盖成功单元任一即失败。详见附件量化条件。

最强代价：共享角色会排队，独立上下文增加成本，owner 仍可能是决策瓶颈。应对不是添更多岗，而是按需调用、明确资产委托；若真实数据证明排队，再调整粒度。原著策划保留为模板而非另建研究 Agent；辩证优化与 QA 验收分开，但小任务免加门。mac 工具缺口如实补证，不偷换机器/装模型。

详细任务卡、证据门、3 个演练的失败标准、最强反对意见与取舍见 `OPERATING-CONTRACT-AND-DRYRUNS.md`。
