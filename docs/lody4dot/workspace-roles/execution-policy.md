# 工作区会话执行规范

本页记录2026-10-26用户明确指定的当前会话选择，适用于本目录所记录的用户Lody工作区；不是lody4dot对所有用户、机器或模型的通用默认。后续用户明确指令优先。

## win-work新会话

- 所有已授权的win-work新会话，显式选择`codex over Claude`所对应的Codex Agent配置。复用已有有效映射，创建前按实际目录核实名称、稳定配置ID及目标机器；不把配置ID硬编码为通用技能默认，不从旧DeepSeek会话或默认选择继承Agent配置。
- 使用Role时核对最终解析的机器与Agent配置仍符合上述选择，不能仅凭Role名称或被Role覆盖的手工参数判断。该Codex配置不可用、目标不明或映射不符时报告具体缺口，不静默降级到DeepSeek、其他配置或其他机器。
- 此规则不修改应用默认、既有会话、已保存Role或模型/强度设置，也不豁免工具安全确认。选择配置不等于授权创建、生产、安装或扩权；每次动作仍须在当前有效授权内。

## 并行与交付

多会话或Codex Cloud的拆分、写入范围、基准与隔离、资源并发、授权等待、独立审查和统一集成，遵循[并行在办任务](../../../skill/lody4dot/references/collaboration.md#并行在办任务)。本页不另复制一套通用流程，也不改写V2.2设计源或历史部署记录。

## 长会话接续

本工作区已获用户／负责人明确批准的同任务接续，沿原责任关系执行[摘要交接→新会话接续→旧会话归档](../../../skill/lody4dot/references/sessions.md#长会话接续与额度单位)，不再把单会话满额当作禁止接续，也不重复请求泛授权。新会话继续遵守上方目标配置及当前工作区准入；新风险、真实总额限制和权限拒绝分别处理。旧执行、资源、成果保全及新端受理按正文取证，实际新旧会话关联只留在获准私密记录中。
