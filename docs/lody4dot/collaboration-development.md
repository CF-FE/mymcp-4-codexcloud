# lody4dot 多宿主协作开发方案

版次：c2，2026-10-21。用户已授权持续实施；本方案定义范围、接口与验收条件，实际进度仅在任务队列维护。正式0.2.1已有共享知识、诊断、平台边界、bootstrap、handoff及Dot接入说明；0.2.2候选增加官方用户setup入口。已核实的产品路线可继续实施，Dot真实接入与多端闭环仍需各自回执，整体目标保持部分交付。

## 1. 目标、依据与完成定义

目标：**同一份lody4dot能力可以在Dot、Codex云端及本地Agent宿主加载或安装，通过Lody服务发现目标、派发任务、交接上下文、观察结果并协作交付。** OpenAI官方确认Dot是ChatGPT中的always-on agent产品，有自己的cloud computer；它也能创建预先配置的Codex云任务，或使用另行授权连接的本地电脑。Dot是具体产品，Agent是参与任务的主体类别，两者不互斥；各执行位置分别建模。

依据按职责区分：[r2产品方案](plan.md)与[d1开发契约](development.md)继续解释原有实现及T01–T12；[环境指引](environment-model.md)、[设计参考](environment-design.md)与[本轮宿主契约](host-contracts.md)提供术语、9篇官方Help来源及证据边界；本方案定义多宿主范围和C01–C10任务卡，实际状态仅由[任务队列](../../.codex/agent-state/todo.md)维护。扩展方案不提前关闭T09/T12，也不自动升级正式环境。

三层交付分别确认，最终目标包含第三层：

| 交付层 | 可验收的结果 | 适用限制 |
| --- | --- | --- |
| 基础安装 | 每个列入支持的宿主能找到并实际读取共享技能，使用已验证的工具入口，报告实际可得版本与角色，版本未知仅告警 | 知识可读、工具可用和执行能力分项记录 |
| 双端协作 | 两个真实独立宿主经Lody面向同一授权任务协作，执行端产物被另一控制端复验 | 同实例子Agent、mock或目录存在不能替代跨端证据 |
| 含Dot多端协作 | Dot经实际支持的工具参与派发或结果交接，本地/云执行节点承担任务，另一宿主复验同一成果 | 人工传递回执只能报告人工交接；全自动闭环须有各端真实调用与回传入口 |

首轮使用自有临时数据和已有授权节点，保持一个协调写入者、一个产物写入者及只读复验者。新增worker、其他操作系统和MCP适配按前提扩展；不以完成部分安装替代整个协作目标。

## 2. 辩证结论与技术路线

保留已有“短技能、按需参考、原生CLI、少量安装诊断工具”的方向；增加宿主接入和协作交接能力。Lody继续拥有资源、会话和业务执行状态，lody4dot负责让各宿主正确使用这些能力。

本轮增量实现针对已确认缺口：共享知识统一为“仅已测自有普通回合取消”，说明`local_runtime:false`相对控制端；doctor保留早期失败前已完成的检查，并汇总可得的包、安装和CLI来源。离线交接校验与依赖bootstrap复用既有能力，不重复开发锁定安装、分页、业务执行或脱敏工具。这些代码和知识能力的存在，不证明新的宿主接入或跨端业务已经通过。

| 候选做法 | 成立之处 | 最强反例或代价 | 本方案采用的修订 |
| --- | --- | --- | --- |
| 只扩充命令说明 | 能补知识盲点 | 已有20根/70路径导航，更多文字不能解决跨端输入、身份与结果关联 | 优先补协作流程、上下文与验收，长尾仍查对应版本帮助 |
| 所有宿主使用同一个安装包和清单 | 共享源码便于维护 | 技能管理、工具、OS和受保护路径不同；当前安装器仅支持Linux；Codex格式不证明ChatGPT已扫描接受 | 共享知识核心，按官方入口准备候选与薄接入材料；实际安装/读取、平台能力分别验证 |
| 所有端都启动daemon | 能把机器作为候选执行节点 | 云控制端不需要daemon；host可能覆盖账户全部工作区，临时云机也不保证长期存活 | 安装、控制、执行角色分开，默认只准备依赖；worker按明确需要单独启用 |
| 全量MCP包装作为统一接口 | 无shell宿主可能需要结构化工具 | 重复已有能力；新增部署和身份映射；导入插件声明远程MCP也可能Desktop only | Dot先复用已有合法连接或委托已准备Codex云环境；只有明确缺口才另行评估最小MCP/Sites |
| 仅靠重置hook重新初始化 | 若事件可靠可自动触发 | 突发回收可能没有退出通知，现有会话hook也不是存储事件 | 幂等准备、入口检查、执行中保存与恢复对账共同工作；hook只是可选触发器 |
| 两端自动抢占和重试任务 | 故障时看似能快速接管 | 当前未证实服务端幂等键或分布式租约，create超时可能已受理 | 首版单协调写入者，未知先对账；跨端接管显式交接，不承诺恰好一次执行 |
| 所有账号共享一个登录目录 | 接入看似简单 | 混淆宿主身份和模型认证，登录态可能进入共享快照 | 各宿主独立凭证通道和私密状态，只交接必要任务资料与引用 |
| 每换产品都重新连接插件 | 易于把连接状态与具体任务绑定 | 官方明确Dot、ChatGPT、Work、Codex共享插件连接及已授予权限；重复连接增加操作 | 复用已有合法连接，分别核对工具实际暴露和动作范围；共享连接不扩大文件、模型或服务权限 |

推荐结构为**共享技能核心＋宿主接入＋平台安装能力＋Lody原生协作**。无需先建立新的任务数据库、全局调度器或通用权限代理。

首批路线按最小增量选择：先让实际宿主读取共享技能；Dot有合法Lody app/MCP连接就复用其已授权工具，否则在可用时委托已准备的Codex云环境使用CLI。Dot自身云电脑直接运行CLI，须另外取得该执行器的工具、OS和身份入口证据；本地技能路线须先有Dot的本地电脑授权。没有缺口证据时不部署新MCP、Sites或自建生命周期服务。

以下执行证据沿用既有[支持矩阵](support-matrix.md)中的受控任务；发布后身份恢复阶段未新增模型回合，后续另有一个明确的远端内置MCP只读验收回合，见队列。

| 目标 | 当前证据 | 最小技术路线 | 进入支持列表的条件 |
| --- | --- | --- | --- |

| Windows上的WSL2 | Linux目标候选，未实测 | 在WSL文件系统内验证Linux路线 | 不称原生Windows支持，不假定与Windows端共享身份和文件 |
| 原生Windows | 现有代码不支持 | 保留知识可移植；原生安装列后续需求，先返回可读的不支持结果 | 文件锁、ACL、启动器、symlink及进程终止均有实现和真实验收后再开放 |
| Dot自有云电脑 | 官方身份、自有电脑及共享连接已确认；本插件加载/CLI未实测 | 优先共享技能和已有合法工具；直接CLI按当前执行器实证 | Dot中的实际读取、工具暴露、身份和结果交接分项回执；不以Codex任务代替自有电脑安装证据 |
| Dot发起的Codex云任务 | 官方支持在预先配置的Codex环境创建任务 | 委托指定已发布环境，使用该任务的技能与CLI | 记录Dot委派关系、任务独立workspace及真实Lody结果；不称Dot自有电脑执行 |
| Dot连接的本地电脑 | 官方支持授权后使用local skills及创建Work/Codex任务 | 本机ChatGPT桌面应用Allow access，保持在线且应用运行 | 本地授权、插件/技能读取、OS/架构与工具分别验证；Codex连接或Work Sync不能替代Dot授权 |

平台前提已集中到`platform_support.py`，不支持的平台在POSIX专属操作前返回结构化结果。当前安装支持仍限定Linux；权限、进程清理、native依赖和symlink激活须在各目标OS实测，不能以隔离导入或通过OS mock宣布跨平台。知识包、宿主插件格式和OS运行时是三项支持维度。

架构预检中的 **DISCOVERY已按有界调查收敛到官方候选路线**：Dot身份、共享连接与Codex委派已有来源；未知范围集中于Dot自有电脑的CLI安装入口、存储生命周期/hook，以及当前账号的实际加载/工具回执。C09可选择已支持路线验收，不必等待未知hook。若确需新增远程MCP，其身份与副作用所有权须单独形成可审查设计，不能在发现任务里顺手部署。

## 4. 模块、所有权与依赖

| 模块及源码位置 | 负责 | 数据与副作用边界 |
| --- | --- | --- |
| 技能核心 `skill/lody4dot/` | 任务路由、命令事实、运行位置判断、协作和核验 | 知识唯一源码；不持有账号、全局任务状态或常驻进程 |
| setup入口 `skill/lody4dot-setup/` | 用户运行插件setup后，按执行器选择已有工具、依赖检查或获授权的准备 | 薄技能只引用核心并复用bootstrap；不持有身份或业务状态，不监听存储事件 |
| 分发 `plugin/lody4dot/scripts/build.py` | 收集核心与已核实的宿主接入材料、包完整性 | 仅生成自包含分发物及已有receipt；不得收集登录态、机器配置和日志 |
| 宿主接入材料 `plugin/lody4dot/hosts/dot.md` | 描述Dot接入路线、共享连接、Codex委派、本地授权和恢复边界 | 随包自包含；每条路线按实际入口验证，不推测通用清单字段 |
| 安装 `install.py`及`platform_support.py` | 锁定依赖、平台路径/锁/激活/检查、失败恢复 | 只写所属安装prefix，复用已有事务；不登录、不注册machine、不启动host |
| 依赖准备 `scripts/bootstrap.py` | 默认离线inspect；显式准备或仅修复缺失运行时后复检 | 只调用已有安装/诊断；不登录、不启daemon、不恢复模型任务 |
| 认证 `auth.py` | verify-only及明确登录 | 宿主独立私密state，Lody账号与模型认证分别管理；不跨端复制身份 |
| 诊断 `doctor.py` / `common.py` | 分项诊断、范围、来源与保守失败分类 | 默认离线，显式连接才查资源；不创建、继续或取消任务 |
| 交接工具 `scripts/handoff.py` | 按阶段校验调用方提供的任务和证据记录 | 只读指定本地文件、向stdout报告；不取回引用、不执行远端业务、不充当任务状态数据库 |
| 主协调Agent与实际执行Agent | 在用户授权内拆解、选择目标、调用Lody并核验 | 协调写入权按本任务约定交接；执行者只写分配产物 |
| Lody服务和执行节点 | 已有资源发现、machine/config、session/turn、派发与观察 | 业务状态以原生返回与持久化观察为准；Operation、schedule按实际作用域使用 |

依赖方向：宿主材料和分发使用共享核心；安装/诊断/认证复用窄平台边界；bootstrap组合已有安装与诊断；交接记录引用原生业务结果；Agent通过已验证CLI或工具调用Lody。Lody业务实现不依赖本插件目录，技能不反向依赖某宿主的绝对路径。宿主专用材料按实际契约增加，不预建通用框架。

安装身份、宿主会话、Lody会话和机器分别识别。首轮复用已有receipt，不强制新增安装ID，更不得用插件关联号替代Codex受保护的`installation_id`。

局部边界记录（BOUNDARY_NOTE）：官方兼容清单增加`extensions.com.openai.onboardingSkill`，由原builder收集唯一的`skill/lody4dot-setup/`，打入`skills/lody4dot-setup/`；包内来源校验只增加该入口文件。保留：核心知识、安装prefix、身份和Lody业务状态的所有权及依赖方向；准备仍由bootstrap组合原工具，setup不增加自动登录或业务重发。验证：移位后的清单目标及核心引用可读，缺失/包外/错误目标、symlink及被修改产物均拒绝，新入口内容修改在receipt对账中可见。

插件连接可按官方规则跨Dot、ChatGPT、Work与Codex复用，但skills安装/管理可能按产品分别进行。共享连接不证明任务已经读取知识，也不复制CLI登录目录、浏览器会话、模型凭证、本地文件访问或全部协作空间权限；实际业务仍受服务ACL和动作授权约束。

## 5. 能力与接口契约

### 5.1 角色与检查范围

角色可为知识读取、控制端、执行节点或控制/执行混合。它们与doctor的`inspect/control/task/worker`检查profile分别记录：请求某角色，不证明具备该能力。

doctor以附加字段`observed_at`、`verified_scope`、`control_environment`与`provenance`报告观察时间、控制端工具位置、范围及插件/CLI来源。保留`schema_version:1`和既有字段；消费方应允许附加字段。2026-10-21按用户要求执行V01修订：Lody版本差异、版本探测失败和可选更新查询失败改为分项`warn`，不使业务检查阻塞或失败，不再沿用旧严格版本退出；其他真实运行、身份、权限和安装完整性失败语义保留。后续其他契约变更仍须单独说明并核对消费方，不静默改变语义。

`0.107.2`仅为知识与默认可复现安装基线。默认inspect/bootstrap离线；doctor只有显式`--check-updates`才查询固定`https://registry.npmjs.org/lody/latest`。非最新版、网络失败或无有效版本数据只告警，不自动升级，不把更新查询结果作为实际CLI命令的执行前提。

失败报告保留此前已完成的checks，未知或未运行项继续如实报告。包receipt、安装receipt与实际CLI版本分别保留来源与一致性；本地摘要不证明发布者身份或签名。账户通过、目录未运行时，两者仍保留原始状态；task/worker不得为消除blocked而改为pass。

原生失败分类不能把代理CONNECT拒绝直接写成目标对象ACL拒绝。保留原始退出码，输出脱敏分类和证据强度；模糊信号保留未知，不自动登录、发布或重试写操作。

### 5.2 最小交接记录

`scripts/handoff.py`已实现schema1项目交接格式，不是Lody或Dot现有API。调用方按实际可观察值准备记录，再使用`--input PATH --stage intent|dispatched|result --json`校验。下面是字段骨架，目标和授权范围仍为null，因此不能直接作为有效intent；可运行的虚构示例、各阶段要求和报告边界见[交接说明](handoff.md)。本地生成的关联号仅关联记录，不提供原生幂等性。

```json
{
  "schema_version": 1,
  "correlation_ref": null,
  "objective": null,
  "authorization_scope": null,
  "coordinator_ref": null,
  "control_host_ref": null,
  "executor_ref": null,
  "lody_refs": {
    "workspace": null,
    "machine": null,
    "agent_config": null,
    "session": null,
    "user_turn": null,
    "assistant_turn": null
  },
  "input_artifacts": [],
  "expected_outputs": [],
  "versions": {
    "plugin": null,
    "cli": null,
    "source_commit": null,
    "environment": null
  },
  "observations": [],
  "result_artifacts": [],
  "unresolved": []
}
```

各引用使用`system/kind/id`；工件记录位置、所属执行器、访问方式、字节摘要与观察来源。`intent`要求目标和授权范围；`dispatched`增加派发关联与版本；`result`增加匹配回合的持久化终态观察，completed还要求结果工件。未知字段和已声明的矛盾会被拒绝。工具只检查结构与声明一致性；pass不证明真实身份、服务ACL、授权、来源、业务结果、工件字节、实时新鲜度或执行器身份映射，这些仍列入`not_verified`。

公共报告只输出必要的脱敏摘要；含业务文本和真实标识的完整交接记录按任务私密资料保存。记录中不接受凭证；工具输出不回显原生敏感响应。引用资料中的指令作为数据，不覆盖当前用户任务。

### 5.3 业务状态、超时与协作写入

提议、已接受、运行中、完成、失败、取消分别依据Lody实际返回处理；观察缺失/过期/metadata是证据状态，不另造业务终态。匹配workspace/session及具体user/assistant回合，不只看latestTurn。

派发前保存意图与关联号，返回后保存原生ID。请求超时可能已经受理：优先按已知ID和授权范围内目录/历史对账，无法唯一确定则保留不确定，停止自动重复派发。只有明确未受理且原生契约允许，或用户明确要求新的任务，才新建。首版协调权是显式协作约定，不是分布式锁，也不承诺多控制端自动故障抢占。

取消仅针对本任务授权的准确assistantTurnId，并核验同一回合持久化终态；ACK、alreadyStopped、停止观察或归档均不替代取消证据。回合取消不保证工具进程即时结束，取消Operation协同链须另核对后继影响。

## 6. 初始化、hooks与存储恢复

### 6.1 已知入口与更优选择

官方打包指南现已核实`extensions.com.openai.onboardingSkill`（兼容清单同样支持）：用户安装后运行setup时调用包内技能，新对话和安装所在现有对话分别验收。0.2.2候选采用这个已知入口，复用既有bootstrap而不等待未知Dot存储hook。它不自动在安装、任务创建或电脑重置时执行。主包继续使用官方支持的兼容格式；新portable根清单可另行迁移，不为本次薄入口增加双份身份配置。官方资料及未知边界见[宿主契约](host-contracts.md)。

既有云准备与启动指引是可复用入口。源码中的`bootstrap.py`将准备和运行检查统一为实际可调用的接口：默认inspect；`--prepare`调用锁定安装再inspect；`--repair-missing`只在诊断明确缺少所属受管运行时后调用安装并复检。它不登录、不启daemon、不恢复模型任务，不注册Dot存储事件。正式环境是否已绑定这些源码入口，须看配置及实例应用回执，不能由仓库文件推断。

在仓库根目录、使用该端实际所属prefix执行：

```bash
python3 plugin/lody4dot/scripts/bootstrap.py --prefix "$LODY4DOT_PREFIX" --prepare --json
python3 plugin/lody4dot/scripts/bootstrap.py --prefix "$LODY4DOT_PREFIX" --json
python3 plugin/lody4dot/scripts/bootstrap.py --prefix "$LODY4DOT_PREFIX" --repair-missing --json
```

第一条用于明确的依赖准备，后两条按入口策略选择；`--prepare`和`--repair-missing`互斥。Lody版本不同或探测失败只告警，不触发重装或业务阻塞；未知prefix、来源损坏等真实失败按原规则报告，不自动覆盖。报告范围为`owned_dependency_readiness`，身份、daemon与任务恢复均为`not_run`。安装器继续检查目录所有权、输入完整性与已有事务规则。

推荐三层恢复，不以重置前回调为正确性前提：

| 时机 | 动作 | 明确边界 |
| --- | --- | --- |
| 环境准备/受支持的重建准备 | 按锁定输入幂等安装，验证CLI/native模块和收据，生成可复用依赖 | 不登录、不登记机器、不启daemon；失败保留旧安装；共享快照不含私密身份 |
| 会话开始/环境恢复后的可用入口 | 先离线inspect，只有明确缺少所属受管运行时才按同锁恢复，随后复检 | Lody版本差异/探测失败只告警；不每次运行完整测试或重装；未知prefix/损坏来源按真实失败报告，不覆盖用户设置 |
| 任务运行与交接 | 在可用且获授权的持久化目的地保存任务关联、必要输入和产物摘要 | 本地临时目录本身不算持久化；凭证与模型认证不进入交接或备份 |

认证在运行时通过已有独立通道进行；已有私密state只验证，确需登录才用原有`LODY_CLI_TOKEN`。启动worker是另一项操作，须有可写执行状态、模型身份、明确机器范围与生命周期验收。控制端恢复不要求启host。

适用对象须先选清：Codex Cloud的已发布setup更新用于新任务，已有任务保留自身状态；新任务创建独立workspace，不能恢复另一任务未提交的更改。官方默认保存VM状态自最近turn启动或任务resume起最多可恢复7天，这不是会话历史保留期，不套用于Dot自有云电脑。重要输入、代码和成果按获授权的持久化通道保存。

### 6.2 hook的适用范围与证据

2026-10-21读取的[官方Codex事件表](https://github.com/openai/codex/blob/c7234c1174b27d9c55199fba0d546dc27d1b0415/codex-rs/hooks/src/lib.rs#L23)包含会话等事件；[SessionStart来源](https://github.com/openai/codex/blob/c7234c1174b27d9c55199fba0d546dc27d1b0415/codex-rs/hooks/src/events/session_start.rs#L23)含startup/resume/clear/compact/fork；[SessionEnd](https://github.com/openai/codex/blob/c7234c1174b27d9c55199fba0d546dc27d1b0415/codex-rs/hooks/src/events/session_end.rs#L20)为teardown事件，默认1秒、最大3秒。

这些是该源码提交的会话契约，不能证明Dot有存储重置通知、当前托管环境允许注册，或Lody使用的Codex0.160.1支持。官方Dot的Reset是用户主动删除Dot及自身对话、记忆和计划任务；创建在其他位置的文件、Codex threads和ChatGPT对话单独保存。它不是周期磁盘重置说明。本轮9篇Help正文与有界检索仍未取得Dot自有电脑的prepare、maintenance、保留目录或重建hook契约，不声明这些接口不存在，也不配置虚构事件。已有Codex准备和共享连接路线继续推进；未来核实到适用hook后复用同一恢复逻辑。

### 6.3 恢复顺序与停止条件

1. 确认实际宿主/执行器及可用加载入口，读取本任务需要的技能。
2. 核对来源、依赖和CLI；缺失时只修复本插件拥有的安装目录。
3. 验证当前运行身份与所需目标范围，不恢复共享快照中的登录态。
4. 从获授权的持久化记录取得原Lody session/turn，再查询实际状态；找不到记录时保留未知，不能按相同标题自动重建。
5. 原任务仍运行则恢复观察；已完成则核验对应产物；失败/取消按原终态报告；没有足够证据则停止依赖操作。
6. 需继续业务时沿原会话发起明确的新回合，记录新的user/assistant标识；不得把“恢复初始化”当继续任务的授权。

恢复演练至少覆盖：依赖保留、依赖丢失、任务运行中控制端中断、结束通知完全未发生、原产物未持久化。不得为演练删除当前宿主卷或用户状态；使用自有临时prefix与记录fixture，再在真实独立目标验证。

## 7. 多端协作纵向场景

首个有价值的闭环为“一个宿主协调 → Lody派发 → 已有授权节点单写 → 另一个独立宿主只读复验”。Dot按已选官方路线取得实际读取和工具证据后加入同一场景，逐步取得含Dot的交付证据。可直接使用[Dot接入与独立控制端运行单](dot-acceptance.md)中的知识目标和只读复验目标；既有任务已具备完整关联时不为补证重复派发。

| 步骤 | 行为与必要证据 |
| --- | --- |
| 定义 | 小型UTF-8输入、确定性JSON输出、输入摘要、目标断言、授权范围与角色明确；不使用用户业务项目 |
| 发现 | 从实际工具读取完整目录，核对工作区、机器与最终配置；Role覆盖以实际生效值为准 |
| 派发 | 主协调者只创建一次，记录实际原生ID；执行节点在自己的获授权临时目录写结果 |
| 回收结果 | 观察匹配回合的持久化终态，并通过受支持文件通道或同会话的只读挑战取得字节与摘要 |
| 跨端复验 | 第二独立宿主读取同一任务关联并核对结果，不再次create、不修改原产物、不启host |
| Dot参与 | 具备合法工具入口时参与调用与汇总；若只能人工交接，明确记录这一限制，不宣称自动闭环 |
| 清理 | 只清理本任务自有临时认证和测试资源，保留既有身份、daemon和会话 |

早期该云实例Codex0.160.1的ACP只读失败不影响控制/复验角色；本轮0.163.0未复测ACP。若目标是让Lody自动派发到云端执行Agent，仍须另验该执行节点的实际写入、身份与模型条件。本地机器休眠或offline时Lody不被假定能代替它完成工作。

输入路径携带所属执行器；路径字符串不等于文件传输。小产物先用已验证的字节读回方法；大产物可评估授权Git提交或文件服务，单独核验访问和完整性，不先开发通用文件同步系统。每个产物首版只有一个写入者，复验者保持只读。

## 8. 顺序、任务与验证

完整静态任务卡及精确依赖表见[C01–C10](collaboration-tasks.md#共用约束与依赖)，状态及实际证据仍在唯一队列。C01产出的官方路线可支撑C05/C09，不把未知Dot hook当共同前置。C05/C06汇合后进行C07。C08本地依赖准备可独立验证，真实宿主重建及业务对账另依赖C01/C05/C07；C09可与双端验证并行，实际接入依赖所选路线的分发、身份与交接证据。最后C07/C08/C09汇合到C10。

C04的实际开放平台、C05的每种清单与C09的工具路线按C01证据决定。各任务的完整前置以卡片为准；C06新增交接工具时完成其对应分发回归，不将它倒置为已完成C05的前置。正式环境更新、实际联网验收和同一任务的副作用操作串行，避免并行写同一prefix或会话。

| 阶段 | 交付物 | 出口 |
| --- | --- | --- |
| A：边界与基础 | 宿主契约表、技能修正、诊断与来源字段、平台边界 | 静态/fixture失败路径有证据，未知接口未伪造 |
| B：可用端协作 | 按宿主打包、交接记录、真实双端闭环 | 两个独立宿主与一个执行节点有角色/版本/结果证据 |
| C：恢复与Dot | 有界初始化恢复、Dot合法接入验证 | 中断后不重复派发；Dot实际读取和工具调用可核验 |
| D：最终复现 | 含Dot协作回执、支持矩阵、上一版本恢复方法 | 整体目标逐项对应真实证据，人工交接与自动链路分开报告 |

现有可用检查从仓库根目录执行：

```bash
python3 scripts/check_repository.py
python3 -m unittest discover -s tests -v
git diff --check
python3 plugin/lody4dot/scripts/build.py --output /tmp/lody4dot-candidate
```

构建输出需选本次新建或已确认自有目录；已有输出不直接覆盖。`handoff.py`、`bootstrap.py`、`platform_support.py`及对应handoff、lifecycle、platform_support测试已在源码中提供，可按[任务卡](collaboration-tasks.md)运行定向检查；命令存在不代表已取得真实宿主或业务证据。真实接入前先做无账户测试；运行类验证只操作已授权的隔离目标，不在CI自动使用真实Lody账号。

关键验收包括：重名/分页、Role覆盖、无shell入口、错误命名空间、非共享文件路径、节点offline、模型身份缺失、创建超时与跨端重复请求、过期回合、取消竞态、重建无退出通知、凭证脱敏。断言实际目标、调用序列和产物，不比对Agent固定措辞，不以关键词检查代替协作行为。

## 9. 迁移、发布与回滚

本轮正式云环境为0.2.1，源码候选0.2.2增加用户setup入口；用户授权的V01策略继续适用。`0.107.2`保留为知识与默认可复现安装基线，实际Lody执行不设版本号门槛。发布后的准备/启动配置无需为相同依赖再次保存草稿或重配token。新宿主包来自同一核心源码，分别记录格式、OS/架构、角色、源码与实际插件/CLI版本、锁和包摘要；CLI版本未知只告警并保留未知。源码候选、正式发布和实例实际版本分别取证；知识更新可复用同锁CLI，不能把知识版本和运行时目录强制一一绑定。

官方支持GitHub marketplace导入和日常同步，但导入只读取内容，不运行本仓库builder。三目录源码需构建后才能含完整技能；不新增catalog指向未构建的`plugin/lody4dot/`，也不提交生成分发物。首轮交付官方支持兼容清单的自包含ZIP候选，构建结果、资源数量和哈希以交付回执为准；ChatGPT web上传/扫描/安装另验。本轮[Plugin Management指南](https://learn.chatgpt.com/docs/enterprise/plugin-management)及打包指南均HTTP200，已核实source和onboardingSkill；ZIP外层包装的UI接受规则仍未知。候选不声明MCP或预设app ID，不以`.app.json`绕过Desktop only限制。

先构建、解包校验和无账户测试，再在单个自有目标验收，最后按真实宿主更新对应安装或配置。发布配置、实例应用、实际读取和业务结果分别取证。未经验证的宿主不进入“支持”列，不自动追latest，不为得到Viewer而换不匹配文件或放宽校验。

旧Linux入口和schema1字段保持兼容，版本提示语义按本轮已授权V01修订执行；后续其他外部契约变更先做消费方验证与独立版本说明。失败回滚仅恢复本插件拥有的上一安装入口或宿主接入材料；Lody会话与任务结果不随插件回滚而删除，用户身份和其他机器配置保持原有所有权。

## 10. 可执行性与当前缺口

**这份方案可直接交接，基础工具与官方候选路线已明确；全范围自动交付仍需真实跨端证据。** 共享知识、诊断、平台边界、离线交接与依赖准备按各自范围使用；Dot所选路线的真实工具/加载、本地OS/架构、独立宿主及执行节点仍需集成回执，缺少哪项仅阻塞相应卡片。实际完成项和检查结果仅在唯一队列记录。

此前9篇Help及四篇官方开发/管理/电脑资料均已读到HTTP200，来源及范围见[宿主契约](host-contracts.md#官方证据与读取范围)。旧实例五条Lody规则、CONNECT403及spec12的unknown均是历史；当前正式ref和readiness统一见[当前环境与下一步](../../.codex/agent-state/todo.md#当前环境与下一步)。HTTPS、依赖、身份、原任务对账与新任务加载各有证据范围，不能由局部通过推导全部服务授权，也不为setup候选重复发布相同环境。

当前有正式Cloud CLI创建入口，但任务目录API返回401，尚无服务核实的ENV_ID，未提交新任务；原生插件UI导入也未提供可调用工具。交付候选和上述运行单，保持相应验收未运行；不以同实例子Agent、子进程或另一目录冒充独立宿主。私密交接工件须通过实际合法渠道送达另一端，同名路径和相同环境发布不证明文件已传输。

后续执行者按队列衔接现有实现与未完成集成，使用任务卡验收，不从头重建工具或重做连接授权。Dot可选择官方已支持的共享连接、Codex委派或已授权本地技能路线；自有云电脑直接CLI和未知hook只限制对应分支。T09旧截图缺少的当时入口/版本、当前发布后恢复的只读证据、新独立任务自动送达并读取技能三项分别核实，互不代结论。Review上游资源与云ACP限制保留各自恢复条件，不使它们无条件阻塞远端控制链路。
