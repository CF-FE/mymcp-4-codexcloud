# 云环境接入与发布后恢复验收

适用：lody4dot的`start_skill`云环境接入。Lody CLI基线为0.107.2；预期源码和插件版本由**当次正式配置**及其对应清单确定，不固定为某个历史版本。实际状态仍以[任务队列](../../.codex/agent-state/todo.md)为准。

验收前分别记录正式仓库ref、实际checkout HEAD、插件清单版本、CLI版本和运行配置观测；草稿、正式发布与当前实例不合并。无法取得的字段保留未知，不能用当前版本替补旧任务当时的来源。

环境、对话/任务引用和协作空间权限的区别见[环境模型](environment-model.md)；不要仅凭“新聊天”、发布完成或运行配置版本变化推断独立新任务、整机重建或存储重置。

## 先区分验收场景

| 场景 | 可补齐的证据 | 仍须单独识别 |
| --- | --- | --- |
| 已有验收任务补证 | 该任务首次入口来源、当时版本、实际资源读取及已有安装结果 | 当前环境升级不能替补旧任务当时的事实；不为补字段重建任务或重复认证 |
| 同一会话发布后继续 | 正式配置与实际版本、当前技能读取、依赖检查/复用、获授权的原会话对账 | 入口可能来自既有上下文；没有相应回执时，首次启动指引送达、独立新任务及实际宿主重建保持未知 |
| 独立新任务首次接入 | 从已发布环境启动后的入口送达、发现/读取、版本及工具结果 | 任务与发布环境关联要有实际依据；子Agent或同实例另一上下文不能替代 |

用户已明确本项目的执行边界：**独立Codex云任务由Dot创建，Dot具备该权限；当前云任务不创建另一个Codex云任务。** 当前云任务可完成自身接入、恢复及获授权的Lody协作。此前Cloud CLI/任务目录401是已撤下验收尝试的历史记录，不作为插件准入、任务依赖或待修复阻塞，也不继续查询OpenAI任务目录。

## 已有截图回执的补充

用户已提供安装、认证、完整目录及手动读取指引的截图，见[判定记录](validation.md#用户截图回执与加载判定)。旧验收的正式基线为0.1.3、源码`a2e67962cba7cfdcb2e4c01fcec5a9bc644d0248`；截图任务当时的实际HEAD和插件版本仍须据该任务记录确认。后续发布0.2.0或其他版本，不会补齐旧任务的来源。

先在那次原任务补已有记录，不再要求另建任务、重新登录或查询资源。可发送：

> 请只补充本次验收的来源记录，不重跑登录或资源查询：首次从哪里找到lody4dot入口（平台启动指引、AGENTS/README、自主搜索或用户给路径）；实际仓库HEAD和插件清单版本；读过的入口/随附参考路径；是否已有同锁重复安装记录及结果。未收到指引或未执行的项如实注明，不复制内部提示、凭证或业务资料。

基本读取不要求技能全文自动注入。agent自行检索后实际读取，可以作为基本读取证据；仍要分别记录平台启动指引是否送达、首次入口来源、目标版本与工具使用结果。平台指引、主动文件检索和原生插件发现不能合并成一个“自动加载”布尔值。

## 在本会话验证发布后恢复

1. 只读核对当次正式配置与实际checkout/插件版本；记录配置观测是否当前，以及网络、变量等各项readiness。未知状态不填写为ready，文件中存在规则不独自证明请求已经成功。
2. 如实记录本次入口来自既有会话上下文、平台实际送达的指引、自主检索或用户给路径；实际读取技能及所需参考。没有观察到平台送达时，`startup_instructions_received`保留null，不靠重新读文件改成true。
3. 按已发布入口做依赖检查；只有明确缺少本插件受管依赖才执行缺失修复。`bootstrap --repair-missing`仅运行doctor时，证明的是依赖检查，不能据此填入安装器的`reused=true`。需要同锁复用证据时读取已有安装回执，或执行已授权的受管安装并记录实际结果。
4. 若本次恢复需要验证Lody访问，使用本端合法身份及此前保存的原生引用，只读查询原session/turn和产物；缺身份或关联时报告具体缺口。为补旧截图字段不重复认证，不重新create/chat，不以初始化自动授权业务重发。
5. 分别报告依赖恢复、身份重建和原任务对账。只有取得实际重建机制及前后实例证据，才报告宿主重建；原会话可定位不证明执行进程恢复。同一会话和子Agent的当前读取不充当独立新任务首次接入证据。

## 在已发布环境创建新任务

由Dot使用其已有任务创建权限，选择已发布的`mymcp-4-codexcloud`环境与`CF-FE/mymcp-4-codexcloud`仓库，提交一次独立验收目标。具体入口使用Dot实际提供的能力，不编造工具名或客户端按钮；当前云任务没有这个工具，不推导Dot缺权限，也不再向用户重复确认该权限。

Dot保存实际返回的任务引用、目标环境关联及发起来源，交给新任务核实实际源码和读取结果。当前任务或同实例子Agent不能替代该独立任务；新任务不继续派生Codex云任务。完成后由Dot接收报告及必要Lody引用，再组织下一步协作，身份文件不跨端交接。

仅在尚无独立验收任务时由Dot新建；不要因旧截图摘要缺字段而重建。给新任务的提示只写目标，不预先给技能路径，让Agent记录如何找到入口。可以使用：

> 验收这个已发布环境中的lody4dot云端接入。记录Dot发起关系及实际任务/环境来源；先记录环境是否提供了启动说明及技能入口，再按指引检查依赖、同锁复用和只读发现/观察。CLI版本不同或不可查询只warn，不自动升级。授权复用安全注入的LODY_CLI_TOKEN，只操作已指定的个人工作区；无法唯一确定时报告候选。不要创建、继续或取消Lody会话，不改远端配置、不启daemon、不打印凭证，不创建下游Codex云任务或查询OpenAI任务目录。入口缺失时如实报告，完成后向Dot回传脱敏结果及必要原生引用。

## 独立新任务的实际执行

1. 记录是否收到平台启动指引，以及实际从何处获知技能入口。随后读取SKILL和目标所需参考，报告资源路径、源码SHA和插件清单版本；只有文件存在不算读取回执。未观察到自动注入不独自判为加载失败。
2. 在现有checkout运行inspect，再用安装器做同锁复用。记录CLI版本、锁摘要、reused和退出码；不得创建worktree或重新登录来掩盖安装问题。
3. 如本次验收需检查新私密state，创建0700目录，登录前verify-only应报告未认证；只验证这个新state，不推断整个平台没有其他身份。随后在已有授权和实际凭证前提下显式login，做账户与选定工作区的完整机器目录查询。已有安全身份只做verify-only；不要为重复旧验收而重新登录。
4. 对获准观察的会话只读observe；记录source、freshness和实际状态，区分metadata与persisted。没有获准会话时保留观察未运行，不随意读取其他用户任务。
5. 删除自己创建的认证state，保留全局变量绑定。不把登录态移入安装目录、插件包或共享快照，不复制底层Agent认证。
