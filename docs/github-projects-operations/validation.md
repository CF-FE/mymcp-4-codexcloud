## 互补事实与异常分类

### 迭代字段

两端反馈相互补充：顶层 `start_date` 在具体方法中必填，即使周期子项已有日期也不能省略；Lody 另验证省略 `iterations` 后返回及回读均为空列表。显式传入三个周期后，日期、时长、标题和周期 ID 可回读，三个周期可赋值，批量接口可切换和清空。

Lody 报告核对了上游固定提交 [`b98d115bbb080e9555466a96656ec4df605aea21`](https://github.com/github/github-mcp-server/commit/b98d115bbb080e9555466a96656ec4df605aea21) 的 `pkg/github/projects.go`：

- [默认描述](https://github.com/github/github-mcp-server/blob/b98d115bbb080e9555466a96656ec4df605aea21/pkg/github/projects.go#L872-L875)声称省略周期列表会自动生成三期。
- [配置构造](https://github.com/github/github-mcp-server/blob/b98d115bbb080e9555466a96656ec4df605aea21/pkg/github/projects.go#L2738-L2779)只在输入包含周期时填充列表，省略时提交空列表。
- [处理函数](https://github.com/github/github-mcp-server/blob/b98d115bbb080e9555466a96656ec4df605aea21/pkg/github/projects.go#L2669-L2811)先创建字段、再处理配置；后段错误可能留下字段是源码层面风险，尚无破坏性负向实测。

本轮本地主线程也实际读取了上述固定提交的处理函数，确认顶层日期必填、先创建字段再解析日期／周期，以及空周期列表原样进入第二次配置 mutation 的顺序，与 Lody 报告的静态解释一致。这不是对线上故障分支的新实测，也不证明远端服务部署了该 SHA。本地 skill 使用明确约定的显式周期列表属于兼容处理，不是服务端修复；不能静默把历史测试的三期、七天或日期变成所有任务的业务默认值。

### 三类失败不能合并成“权限问题”

| 观察 | 来源与处理 | 能得出的结论 |
| --- | --- | --- |
| `Resource not accessible by integration`／HTTP 403 | 云端先导读取及视图创建前置解析失败；公子批准权限后，同一插件读取和后续写入成功 | 与新增权限待批准吻合，但报告未独立读取实际凭据 scope、App 配置变更或审批后台记录 |
| Issue #5 关联被安全检查拦截 | Lody 临时资源授权未明确覆盖此关联；停止该分支，没有换工具或重复提交 | 本次执行授权阻断，不能记录为 GitHub ACL 拒绝、API 行为失败或已测通过 |
| 关闭项目不能创建视图；缺顶层 `start_date` | 云端保留 #2 的关闭状态，使用已获准开放测试对象；补全参数后重试迭代字段成功 | 对象状态及参数前提须分别定位；外层 `INVALID_ARGUMENT` 曾包装不同底层错误，不能据外层码单独分类 |

两端没有报告测试后自动扩权、复制凭据或借备用接口绕过拒绝。Lody 端没有备用 `gh`／浏览器清理通道，不影响其已有认证 MCP 成功操作私有项目的事实。

### 状态、分页与批量

- 云端两条关联刚加入 #4 时，首次读取的 Status 已为 Done，添加请求并未指定它。原因未核实，可能涉及默认工作流；不能推定新条目为空或自动业务验收通过。
- 两端都验证过字段前向分页；云端字段分页期间发生过本轮字段新增，因此未建立一致快照保证。空、`null`、过滤结果及分页完整性须按原响应范围解释。
- 云端的两条批量结果全部成功，但其中一个结果缺数字 `item_id`、有 node ID 与 `full_database_id`；不能要求每条结果形状完全一致，也不能把这次全成功推广为部分成功或 UNKNOWN 的恢复已验。
- Lody 验证了迭代字段的 `null` 清空；不能推广为所有字段类型均支持同样清空语义。
- 两端均未调用修改源 Issue／PR 正文、标签、负责人或原始状态的接口。条目回读保留原关闭／合并状态和原更新时间；关联操作是否生成时间线、通知或额外审计记录未核验。
