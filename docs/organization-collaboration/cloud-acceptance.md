# 云端接入与复核验收

本说明配合交接消息中的**完整固定提交SHA**使用，不能用移动的`main`替代验收版本。目标：组织协议1.3.0、Projects操作skill1.1.0、组合包0.7.0；专业库1.1.1不变。正文是验收流程，不是对远端已经安装或实际任职的宣告。本轮本地证据见[验证记录](validation.md)。

## 1. 保留现场并取得固定源码

先核现有checkout的分支、提交、未提交修改和在途任务采用版本。使用已有获准GitHub连接取得交接SHA；可复用干净checkout，存在无关修改时保留它们并使用新的验收目录。不要reset、清理旧包或把已有任务重开。固定为detached后，回报完整`git rev-parse HEAD`、实际路径及执行端。不能取得固定提交时只报告缺口，不拿相似版本替代。

组织或技能记录实际看板、负责人、当前写者及读取通道来自受控项目记录。用户提供的私有项目看板仅有创建事实时，不宣称任务登记、补录、负责人接入或切换完成；准确编号和会话绑定不写回公开仓库。各角色优先正式看板及关联任务／有效回执，未切换的任务仍沿原正式入口。

## 2. 检查与新目录构建

仓库根使用Python3.10+标准库：

```bash
python3 scripts/check_repository.py
python3 -m unittest discover -s tests -v
```

选择一个全新的输出父目录，下列命令的`/tmp/intake-new`是示例，实际使用前核不存在，不能复用覆盖旧包：

```bash
python3 plugin/lody4dot/scripts/build.py --organization-skill-only \
  --output /tmp/intake-new/organization-collaboration-1.3.0 \
  --zip /tmp/intake-new/organization-collaboration-1.3.0.zip --json
python3 plugin/lody4dot/scripts/build.py \
  --output /tmp/intake-new/lody4dot-0.7.0 \
  --zip /tmp/intake-new/lody4dot-0.7.0.zip --json
```

核两包收据、ZIP CRC、成员集合、逐文件SHA与固定源码一致。组织独立包10份Markdown＋收据，组合包61个内容文件＋收据；新增auditor和追溯参考必须在组织独立包及组合包出现，原路径保护继续生效。跨宿主ZIP摘要不同不单独判损坏，优先核成员内容、收据和CRC。

Projects技能完整目录`skill/github-projects-operations/`独立交付，含入口、3份参考及1个日期脚本共5文件，不在组合包内。用固定Git文件清单复制到新的持久可读目录，逐字节／SHA比对并保持相对结构；不要复制缓存。无需安装Lody CLI、认证或启动daemon来验证这两项组织／记录技能。

## 3. 按岗位实际读取

所有接入端读取组织`SKILL.md`，再按本次岗位读取必要参考。审计岗位新增定义不自动任命任何人，不授予跨项目权限或定时执行。

- 总协调：`organization-lead.md`，新派发／恢复时读`task-traceability.md`；本组织由Dot承担，项目最终验收仍归项目负责人。
- 项目负责人：`project-owner.md`、`planning-and-progress.md`及本次记录／回执。
- 执行者／质量审查者：`execution-and-review.md`对应段；分别保留自检、独立复核和负责人验收。
- 实际获任命的审计者：`auditor.md`、`task-traceability.md`；确认范围、来源覆盖、报告接收者、争议路径及参与回避。
- 记录写者：`authorized-recording.md`；实际GitHub操作时读Projects技能入口与所需`query.md`或`changes.md`，只读不必加载写入全手册。

本次需要采用的岗位尚未绑定时明确待确认；未安排审计则记不适用，不阻断无依赖的接入步骤。可以完成离线岗位理解测试，不能把测试参与者冒称正式任职。普通在途任务按明确节点采用新版，引用与已发生事件保持；撤权、新指令和安全约束立即适用。已有旧目录或自定义改动不覆盖，新会话原生发现若未验就如实写未验，显式读取与原生自动发现分列。

## 4. 离线行为复核

评测者只拿[场景输入](eval-inputs.json)及完整技能，先独立给出动作，再由协调者用[判据](eval-rubric.md)评分。保留实际读取文件、原回答、逐项判定和未验项；两个上下文各处理一组场景可复现本地方式，但不等于16次独立实验。

重点检查E01–E16：看板优先但不压过有效新指令；UNKNOWN与意图恢复；已建执行登记失败；批量与并发；必验未验；取消但原生状态未知；历史补录；WAV就地复核；漏登来源与不完整覆盖；自审回避与上级争议；私有内容误投公开仓库；在途切换；可选审计不扩大停工；统一入口不可读时的定向恢复。

这轮不得为凑验收重跑20种写方法、重复创建执行任务、创建／重开测试板、启动音频生产、做未经授权的通知或调整权限。

## 5. 真实只读与切换边界

复用各端有效连接证据，仅在已获授权的准确项目上做本轮需要的定向读取。读看板元数据只证明看板；读任务进度须显式取得相关字段，并核关联任务／版本及观察时间。需要全量结论才完成相应分页和来源对照，不把字段定义读取当条目值读取。权限或工具缺口明确归属，不借换连接绕过拒绝。

实际登记／迁移需另外核明确对象、可见性、安全落点、写者及有效决定。这份接入验收说明不授权业务写入。先复核旧任务到新入口的映射、原生执行关联和待补写事项；某任务切换确认后旧入口只留历史与指针，未完成迁移的任务仍由原入口负责。不因部署规范创建另一套正式进度。历史补录保留发生和登记时间、来源与缺失项。
