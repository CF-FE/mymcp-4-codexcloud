# 项目资产归档与交付迭代

2026-10-28，设计版本1.0。公子已批准本轮规范与模板迭代并启动Goal；本页记录经review收敛的需求、组织适配及验证边界。运行规则唯一正文为[资产归档参考](../../skill/organization-collaboration/references/asset-archiving.md)，原任务、回执和实际采用继续由[任务队列](../../.codex/agent-state/todo.md#当前环境与下一步)及各项目正式入口维护。归档规则不授权实际上传、迁移、权限变更或脚本执行。

## 目标与边界

让项目资料能查阅、追溯并按约定恢复或复建，同时避免二进制历史膨胀、秘密泄露及独立可修改副本漂移。复用已有仓库、制作端、协作空间和任务记录；不新增归档数据库、上传服务、全量历史迁移或默认付费存储。

架构路径为`BOUNDARY_NOTE`：增加可引用的资产身份、来源／副本、保存与恢复证据信息，保留项目负责人业务决定和验收、资产当前写者、原生存储及任务事件各自权威。索引维护资产事实；采用与验收只引用原正式记录，不拥有第二套状态。现有“音频原件不进入任务日志”继续有效，它不是“媒体一律不得入项目仓库”；环境仓库不提交分发生成物、依赖缓存和凭证的规则也不因此放宽。

## review后的实施取舍

| 问题 | 本轮处理 |
| --- | --- |
| 按扩展名禁止全部媒体，或把小文件一律允许入库 | 按用途、体积、数量、变化频率和公开授权判断；可以版本管理的小媒体与大型／频繁产物分别选路 |
| 原件只留执行端就称可恢复 | 记录原件保管责任、所属执行器、准确位置和持久性；临时位置与缺恢复入口明确标注，不自动新建备份服务 |
| 有依赖锁或脚本就称复建成功 | 归档说明、原件可取得、恢复／复建验证分别记证；外部模型素材引用也要精确，生成结果不默认字节可重现 |
| Git索引另写“正式”，与负责人回执漂移 | 索引记录内容和关系，状态摘要带正式决定／验收引用及观察时间；上传不推动任务关闭 |
| 每次上传重做全部QA和授权确认 | 复用仍有效的批次授权与同表示内容证据，只补发生变化的传输、访问、内容或呈现检查；已有必验不跳过 |
| 回读LFS指针或网页预览就称原件收到 | 精确引用目标提交／文件或实际工件，核所需原字节；预览、下载、播放与质量分别取证 |
| 按工具调用拆批绕软阈值 | 采用时按同一任务一批归档变更计新增／替换媒体完整大小，不按diff或单请求大小；高频增长另评估 |
| 秘密误传只删除当前文件 | 停止传播，由有权责任人优先撤销／轮换有效凭证，再评估历史与副本处置；不自动改权限或重写Git历史 |

## 本组织采用政策与项目实例

本组织协作空间继续用于可传输文档、台本、方案、规范、索引和复核报告；媒体查阅引用已获准项目仓库或原存储对象，不为中转另造媒体库。这是组织采用政策，不是平台不支持媒体的结论；既定附件交付或手机试听仍按任务约定履行，不被GitHub归档替代。

公子在本次需求中确认：凡人项目可公开的小体积媒体已获准归档到`CF-FE/fanren-work`，完整素材、母带、模型及正式成品的原件保管位置仍按项目的win-work记录核实。这一声明不授权上传尚未核公开范围的素材，也不把其他项目自动路由到该仓库。准确私人路径、原生会话和保管人绑定仍留受控索引。本轮不执行该项目媒体上传或历史迁移。

建议评估的软阈值为单文件10 MiB、一批媒体归档变更合计50 MiB，当前仍未启用，不是GitHub平台上限，也不是小于阈值就必然适合入库。项目需明确采用范围、依据、例外决定者与复核条件；超过软阈值时评估用途和增长成本，复用有效授权选择合适落点，不默认拒绝、转码、开通付费LFS或拆批规避。累计体积和频率按有意义的变化／复核点评估，不要求每个文件都扫描完整Git历史。

## 最小实施

1. 在组织skill新增一份平铺参考，含按用途路由、来源与用途副本、保管／恢复、公开范围、软阈值解释、最小索引和写后回读；从入口、产物回执和追溯正文短链接进入。
2. 资料交接参考只引用通用规则，保留引用类型、真实字节／提取文本／摘要及保存与回读的既有区别。Projects操作skill继续管理任务记录，不扩为资产上传工具；实际工具能力在具体任务中核查。
3. 复用既有岗位，不新增归档专职角色；项目负责人确认维护来源和交付要求，受托执行者维护资产和证据，审查者按明确版本与必验范围复核。旧资产无本轮迁移授权时保留原位。
4. 组织协议1.5.0、组合0.9.0分别标识新增能力；Projects skill1.1.0、专业库1.1.1和运行脚本／依赖锁不变。按需读取新增参考，不把全套索引变成小文件修改的必填表。

模板复用既有字段，最少能定位任务／用途、维护来源与版本、表示类型、原件与副本关系、真实字节属性、准确仓库提交或原生工件、访问范围与保管责任、恢复依据，以及正式采用／验收引用。能由Git直接取得的版本无需人工重复填写；不把索引所在提交SHA反复写回自身形成循环。

## 验证与采用

在原行为输入和判据追加A系列，覆盖公开范围不足、敏感配置、软阈值未采用／已采用、同字节复用、部分成功与UNKNOWN、摘要不一致、预览不能代替播放、候选未验收、原件保管、复建缺输入、LFS指针及实际媒体、秘密误传、迁移未授权、增量复验和索引状态漂移。评测者先独立回答再评分；不上传真实资产或制造泄露来测试。

运行仓库结构、技能格式、引用与必要Python检查；构建组织独立包和组合包并核成员、CRC、逐文件SHA及来源。不新增匹配措辞的测试或上传服务。原E/P场景与历史回执保留，涉及真实端侧访问、播放、恢复或复建的能力仍须具体任务证据；规范通过不代表生产已验证。

受影响端在明确节点读取组织入口、新参考及本次岗位正文；具体项目在已有正式入口确认存放政策、可公开范围和必要阈值，未采用继续原有效规则。新版本不自动迁移旧文件、不覆盖原件、不改变既定验收或在途任务。结果统一追加到[验证记录](validation.md#150项目资产归档与交付)，Git交付以最终回执为准。
