# 局部阻塞分流与兜底需求说明

本页集中记录2026-10-31用户已确认的需求与方案取舍，供[Draft PR #10](https://github.com/CF-FE/mymcp-4-codexcloud/pull/10)的本地review与优化使用。运行规则仍以[阻塞分流主规则](../../skill/organization-collaboration/references/planning-and-progress.md#403等局部阻塞的独立会话分流)和[授权记录者适配](../../skill/organization-collaboration/references/authorized-recording.md#服务故障时的最终代办)为准。

## 背景与目标

本需求针对三类协作风险：局部403或Projects MCP不可用拖住独立主线；只转发错误或登记下一责任人，缺少实际处置闭环；跨连接接手产生重复写入或绕过访问拒绝。目标是在既有授权内隔离受影响步骤、推进独立工作，形成可核查的操作与反馈闭环，并逐对象交还单写职责。

## 用户已确认的要求

- 先核403实际来源与性质。需要持续排障时使用独立会话，同源问题复用已有排障关联；不受影响的主线继续。排障事实直接报本次指定协调者云端Dot，并同步项目负责人（owner），业务验收权保持原归属。
- 云端Dot接住冒泡阻塞后，负责合法方案选择→实际操作→结果验证→反馈／交还；可恢复且获准的步骤继续落实。只有真正不可替代的授权、身份或用户／平台动作才集中明确提出，不能以原样转发错误或收件ACK结案。
- Projects服务故障时，项目负责人先完成可做准备，汇总准确Project／Issue／Item、失败动作与证据、已完成项、受影响／可继续范围、当前值→目标值或具体操作、决定依据、已有请求引用与结果（含UNKNOWN）及单写边界；云端Dot使用自身现有可用且获准的连接最终代办，同对象回读、反馈并确认交还。
- 失败性质UNKNOWN、写入／派发结果UNKNOWN及已发生效果分别取证；未知写请求按原引用对账，不重放。明确拒绝不能通过换会话、主体、工具路径或执行器重做，代办仍核准确落点、可见性和操作范围。
- 本次具体协调者统一称“云端Dot”，专属绑定见[CF-FE适配](github-projects.md#2026-10-31lody服务不可用时的最终兜底)；完成后提交draft PR交本地会话review与优化，不自行批准或合并。

## 方案取舍与范围

| 决定 | 理由与边界 |
| --- | --- |
| 归现有协作规范 | 复用已有局部阻塞、岗位责任、UNKNOWN、验收及单写交还约束，避免独立skill产生重复入口和规则副本。 |
| 持续排障才独立分流 | 小任务沿既有粒度规则在原任务内处理；同源复用、预算与停止点限制会话膨胀，不为每个报错开新会话。 |
| 通用职责与专属绑定分层 | 通用skill只写职责称呼；本用户的Lody／云端Dot绑定留在CF-FE文档，不成为其他用户默认。 |
| 日常写入保留原分工 | 云端Dot承担已冒泡、已指定兜底的最终闭环责任；日常查询和登记仍按原职责及逐对象写入范围执行，避免集中所有写入。 |
| 工具步骤沿原入口 | 具体读写引用[Projects操作skill](../../skill/github-projects-operations/SKILL.md)，故障定位使用目标端已有获准诊断入口；协作规范不另维护API操作副本。 |

非目标：新增skill、岗位或自动调度器；硬编码通用用户名；扩大权限或绕过拒绝；保证所有403都能解除；迁移在途任务、重装旧包，或操作真实业务来凑验收。本次需求文档补全也不改变技能行为、版本、测试用例或构建物。

## 验收与追溯

以[固定输入](eval-inputs.json)及[原判据](eval-rubric.md#p系列局部阻塞与并行交付)追溯下列要求，实际检查及失败记录见[1.5.1验证记录](validation.md#151阻塞分流说明补丁)。

| 验收点 | 对应要求与证据 |
| --- | --- |
| 入口可发现 | 组织README的[1.5.1小节](README.md#151阻塞分流说明补丁)可达本页；[skill入口](../../skill/organization-collaboration/SKILL.md)可达主规则与授权记录者正文。 |
| P18：局部隔离 | 核错误来源、只隔离受影响步骤，交有限排查包，主线继续；派发、受理、执行和核验分别取证，不转移原写权。 |
| P19：UNKNOWN与拒绝 | 原动作、响应及副作用分别保留，未知写请求按原关联对账；不补造权限结论、不重放、不代批未知权限卡。 |
| P20：实际检查能力 | 检查绑定精确版本和实际覆盖；缺听辨能力记未验，不以格式检测或旧版本报告虚称已听、已通过。 |
| P21：代办闭环 | 准确对象、当前→目标／具体操作及决定依据齐备；可执行操作须同对象回读、反馈，并确认逐对象单写交还；ACK不代替完成。 |

三个关键反例均须拒绝：另开会话强写受拒动作是绕权；MCP故障停全项目是扩大阻塞；API成功却无同对象回读是假完成。

文档、源码检查与离线回答仅证明各自覆盖范围；平台访问恢复、技能加载、真实操作和实际核听仍须对应运行证据。旧失败及历史验证保留原范围，不因本页补全重新判定或扩大结论。
