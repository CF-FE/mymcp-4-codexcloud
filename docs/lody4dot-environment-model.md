## 1. 概念与总览

![当前会话经云工具运行Lody CLI并访问远端Agent；本地和协作空间均需单独接入。](diagrams/environment-context.svg)

[Mermaid图源](diagrams/environment-context.mmd)。实线表示本次已验证的主要调用关系，虚线表示配置恢复或有前提的接入；连线不表示共享权限。

| 对象 | 职责与本次对应 | 不应混同的状态 |
| --- | --- | --- |
| 客户端 | 用户输入与查看结果的界面，可以在电脑或浏览器上运行 | 客户端在用户电脑上，不代表命令就在用户电脑上执行 |
| Agent / Dot | 接收目标、推理并调用当前可用工具的执行主体 | 执行位置取决于实际工具连接，名称不决定文件访问或外部账户权限 |
| 聊天会话 | 消息、可见历史、附件与工具结果的上下文 | 新聊天不独自证明新云任务、新机器或相同发布环境 |
| 云任务 | 平台建立并绑定运行环境的一次工作单元 | 是否存在独立任务及其来源需平台记录或任务回执；不能靠窗口名称推断 |
| 环境配置 | 仓库来源、安装/启动说明、网络和变量绑定等设置 | 草稿保存不代表已发布或实例已更新 |
| 发布版本 / 快照 | 平台激活的配置版本及其保留的安装状态 | 不保证现有任务全部更新，也不保证活进程和登录态恢复 |
| 云执行实例 | 真正运行shell并存放当前 `/workspace` 文件的实例 | 底层可能是容器或虚机；不根据新任务就断言新物理主机，也不推断所有任务共享同一实例 |
| 云主机 / 基础设施 | 云上的计算承载，如虚拟机或服务器，可承载运行实例 | 当前底层拓扑未核实；任务ID、实例ID和主机ID不能互换 |
| 用户本地环境 | 用户电脑自己的文件、进程、CLI、配置与身份 | 当前云工具未因此获得用户电脑的访问权；须有明确接入的本地工具 |
| 子Agent | 分工处理当前目标的另一个Agent上下文 | 本次共享执行实例；新上下文不等于独立云任务 |
| 协作空间 | 用户所说的产品共享会话、文件或其他协作对象 | 与云执行器目录和Lody workspace分别授权；不能用列出 `/workspace` 代替枚举协作空间 |
| Lody workspace / machine / session | Lody业务工作区、执行节点和任务会话 | 不等于当前聊天、云任务或协作空间；一个machine可能在本地或云端 |
| Git仓库与工作目录 | 代码来源、版本和实际checkout位置 | 同仓库可以出现在多个实例；同一路径文字也不能证明是同一文件系统 |
| 插件包 / skill / MCP | 分发单元、操作知识、工具服务等不同能力形态 | 文件存在、安装完成、技能读取和工具可调用分别验收 |

Lody内部也要分别识别：

| Lody对象 | 职责 | 不能由此推导 |
| --- | --- | --- |
| workspace | Lody业务资源与授权的工作区 | ChatGPT协作空间权限 |
| machine | 被Lody识别的执行节点，可在本地或云端 | online不证明所有Agent或模型可执行 |
| agent config / Role | 执行配置或角色绑定；Role可能覆盖手工参数 | Lody登录不提供底层模型凭证 |
| session | Lody中的业务会话 | 不能替代当前聊天或云任务 |
| user turn / assistant turn | 用户请求与对应执行/回复回合 | 两种ID不能互换；取消参数要求assistantTurnId |

本次已通过的远端链路是：用户客户端中的当前会话，由agent调用云执行器上的Lody CLI，再通过Lody访问已有远端machine/config及自有验收session。控制端与执行端不同，不要求控制端启动daemon。

“本机ACP只读失败”中的本机，是当前云执行实例内部的Codex runtime，不是用户电脑。当前子agent共享执行环境；即便使用独立上下文，也不能代替平台新任务的初始化和环境恢复验收。

同一台电脑可以同时扮演客户端、本地执行器和Lody machine；这些是角色，权限不会因此合并。“本地Dot/云Dot”应具体说明使用哪个执行工具，不能由客户端所在位置推断命令或模型服务的位置。

## 2. 标识与引用

不同系统分别命名和检查访问。不要只保存一个没有来源系统和对象类型的 `session_id` 或 `environment_id`。

| 引用 | 可以定位什么 | 不能单独证明什么 |
| --- | --- | --- |
| ChatGPT/Codex对话引用 | 某个对话或平台提供的有界预览 | 全部历史已读取、附件均可取、拥有其协作空间权限，或继承其运行环境 |
| 云任务标识 | 某次平台工作的来源与绑定关系 | 当前工具能操作它，或该任务与当前实例相同 |
| 配置标识与发布版本 | 某套环境设置及其版本 | 所有现有任务都已切换，或安装包、源码、指引均被加载 |
| 运行实例标识 | 特定运行环境的状态与工具作用域 | 自动拥有其他实例的文件、进程和身份 |
| 实例标识 + `/workspace/...` 路径 | 指定执行器里的文件 | 另一台机器的同名路径、协作空间中的同名资料 |
| 上传文件标识 / Page标识 | 所引用的文件或页面对象，实际读取须经工具访问检查 | 整个目录、空间或全部相邻资料可读；链接本身不扩大服务端访问权限 |
| Git远端 + commit + checkout | 代码来源与某个工作副本的版本 | GitHub API、Lody或空间访问权限 |
| Lody workspaceId / machineId / sessionId | Lody目标资源 | 可替代ChatGPT对话或云任务标识，或自动取得底层Agent凭证 |
| Lody userTurnId / assistantTurnId | 请求与对应回复回合 | 两个标识可互换；`session cancel --turn-id`要求assistantTurnId |

引用作为数据处理。是否能读取完整对象，取决于当前实际可用的工具、它的访问检查和返回范围；收到一个链接不等于收到对象的所有内容，更不扩大到整个空间。跨会话也不能假定环境、登录态或完整上下文随链接传递。

用户明确要求读取某个链接，可以构成对该目标的任务授权，但仍须满足服务端访问检查。交接时传递来源、目标、版本、授权范围和证据；真实任务/实例/会话标识保留在私密关联记录中，公开报告使用脱敏引用和结果。

## 3. 版本与生命周期

![保存、发布、实例应用、指引送达、技能读取和业务核验分别取证，前一步不保证下一步。](diagrams/environment-lifecycle.svg)

[Mermaid图源](diagrams/environment-lifecycle.mmd)。这是验证流程，不是保证所有步骤自动成功的平台状态机；自主检索读取与平台指引引导分别记录。

| 阶段 | 所需证据 | 不能替代下一步的原因 |
| --- | --- | --- |
| 草稿已保存 | 后端确认保存字段与版本 | 保存不执行安装、发布或实例更新 |
| 环境已发布 | 平台激活版本的记录 | 现有任务可能仍绑定旧版本 |
| 实例已应用 | 实际实例状态、代码版本及相关操作 | 文件恢复不证明进程存在 |
| 启动指引已送达 | 该任务实际收到指引/入口的来源记录 | 指引存在不证明Agent已读取 |
| 技能已读取 | 实际读取入口、参考和工具的记录 | 读取不证明账户和模型可用 |
| 工作流已验证 | 准确目标、持久化结果及必要产物 | 一次成功不能推广至所有配置或平台 |

| 状态或资料 | 跨任务/发布是否保留 | 正确处理 |
| --- | --- | --- |
| Git源码、插件包、来源记录 | 可按版本保留 | 分别追踪commit、包版本和哈希 |
| 依赖、工作目录、安装文件 | 取决于快照契约及实际恢复 | 在目标实例核对路径、版本和重复安装 |
| 进程、daemon、网络连接 | 不假定保留 | 需要时在运行阶段启动并验证 |
| 变量/凭证绑定 | 按平台绑定与注入规则 | 存在性、ready状态和真实授权分别检查 |
| 任务私密登录态 | 不进入共享包或安装快照 | 运行时显式认证，清理自有临时state |
| 对话历史、附件 | 按当前上下文和读取工具决定 | 记录实际读取范围，不假定完整继承 |
| Lody业务会话 | 由Lody持久化与资源权限决定 | 用workspace/session/turn及observe核对 |

发布版本、Git提交、插件版本和CLI版本是四个维度。不能只报告“最新”，也不能由网络revision未变推断源码未发布。

## 4. 权限与访问判定

![用户授权、工具与服务端检查、实例权限、目标账户权限共同限制执行，缺证据保留未知。](diagrams/environment-permissions.svg)

[Mermaid图源](diagrams/environment-permissions.mmd)。明确拒绝、缺少工具和未观察应分别报告。

实际可执行范围受以下边界共同限制：用户给出的任务授权、当前提供的工具及服务端访问检查、执行实例的文件/网络权限，以及目标系统账户的资源权限。任一项不满足都不能靠另一项替代。

| 权限层 | 决定什么 | 本次例子 |
| --- | --- | --- |
| 用户任务授权 | 允许哪些操作和目标 | 允许测试已有Agent，不自动扩大到其他workspace的写操作 |
| 工具与连接器 | 可通过什么接口接近资源 | 当前没有整个协作空间的枚举工具 |
| 服务端对象访问 | 身份可读取/修改哪些对象 | 会话链接不能绕过空间或文件ACL |
| 执行实例权限 | 文件可写位置、网络和受保护配置 | `/workspace`用于工作，Codex受保护状态仍可能只读 |
| 外部业务权限 | 账户、工作区、机器和具体操作范围 | Lody资源可见、可用和实际执行分别核对 |
| 底层Agent认证 | 真正调用模型的执行身份 | Lody凭证不代替Codex等模型认证 |

- 协作空间按实际登录身份和对象访问规则检查。当前会话没有可枚举整个协作空间的工具；没有可见Page也不代表用户没有空间或权限。不能把用户在界面可见的内容当作agent已获得的资料。
- `LODY_CLI_TOKEN`仅用于Lody账户访问；当前实际注入和认证已分别验证。它不提供当前聊天的认证、用户电脑的访问、受保护Codex目录的写权限，或底层模型执行凭证。
- 环境变量按平台的绑定和注入规则生效；“全局”不证明其他产品、其他环境或用户电脑也收到同一变量。发布物与共享快照仍不能包含任务登录态。
- Lody选择一个workspace是在指定业务目标，不会自动缩小token本身可见的全部范围。任务仅授权个人workspace时，不能因此写其他workspace；启动host的全工作区订阅范围须另外评估。
- Git代理认证只在其支持的请求范围使用；仓库访问不等于GitHub API、Lody或协作空间权限。机器online、CLI可运行与模型任务成功分别核验。
- 子agent不会增加权限；它们共享当前工具允许的执行范围与文件系统，仍受同一用户授权约束。
- 读取、修改、发布和发送消息分别判断授权与服务端权限。有权读取共享文件，不代表可以更改空间成员、发布内容或替用户向他人发送消息。

## 6. 交接与验收

| 场景 | 正确做法 | 容易产生的误报 |
| --- | --- | --- |
| 用户引用另一会话 | 使用可用工具与访问检查，注明预览/完整范围 | 收到链接就声称全部历史已读取 |
| 用户说“空间里的插件集合” | 按产品对象和空间工具定位，缺入口时报告能力缺口 | 用 `/workspace` 目录代替协作空间 |
| 新开聊天/任务 | 记录实际任务来源、环境版本和执行绑定 | 凭新窗口声称新机器或同一环境 |
| 发布环境更新 | 保存、发布、实例应用分别核对 | 要求重复发布已生效的相同设置 |
| 自行搜索后读取skill | 记录首次发现来源和实际读取参考 | 未自动注入全文就判加载失败 |
| 截图摘要缺字段 | 在原任务补已有记录，未运行项如实保留 | 重建任务、重复登录或把截图当原始日志 |
| 派发到Lody远端 | 保留控制/执行端、session/turn、持久化结果 | 用控制端路径或online代替执行成功 |

最小回执包括任务来源、代码与插件版本、指引发现来源、已读资源、工具所在执行器、各项检查结果和清理范围。未知字段保留未知，不补造标识或复制内部提示。已有截图按[补充流程](lody4dot-fresh-task-acceptance.md#已有截图回执的补充)完善，不重新登录或查询。

## 7. 架构设计参考

本节是建议模型，不声明平台已经提供这些实体、字段或API。

| 建议记录 | 应记录的关联 | 设计目的 |
| --- | --- | --- |
| Agent与工具连接 | Agent、连接、目标执行器/业务系统 | 同一会话接多个环境时仍能定位操作位置 |
| 会话与任务 | 系统命名空间、会话引用、任务引用和来源 | 不用一个session字段混装各系统ID |
| 任务与实例绑定 | 任务、实例、发布版本和生效时间 | 不预设一对一，不用最新值覆盖旧绑定事实 |
| 源码与发布物 | commit、插件版本、CLI版本、包哈希 | 解释代码、环境和安装版本不同步 |
| 资源引用 | 所属系统、对象类型、标识和来源 | 定位对象，不把引用当作凭证 |
| 授权与访问结果 | 用户范围、工具/对象检查、拒绝/未知原因 | 分开记录允许做、技术可访问和实际执行 |
| 执行与证据 | 控制端、执行端、session/turn、产物和观察时间 | 可沿操作链核对结果，保留证据来源等级 |

建议的最小来源回执：

```json
{
  "observed_at": null,
  "evidence_origin": null,
  "conversation_ref": null,
  "task_ref": null,
  "runtime_ref": null,
  "environment_version_ref": null,
  "repository_commit": null,
  "plugin_version": null,
  "entry_discovery_source": null,
  "resource_reads": [],
  "access_evidence": null
}
```

这是项目建议格式，不是平台API。未暴露/未观察字段保留null；填充各ref时应同时记录来源系统、对象类型与标识。evidence_origin区分平台工具、Agent记录、用户截图；resource_reads只记录实际读取；access_evidence记录授权和检查结果，不记录秘密值。私密标识与公开报告分开保存，不用占位值冒充真实对象。

后续架构评审至少检查：

1. Agent、会话、工具连接和执行位置是否分别识别？
2. ID是否带来源系统和类型，任务/实例绑定是否有时间和版本？
3. 引用、用户授权、服务端访问与凭证是否分别处理？
4. 保存、发布、应用、送达、读取和业务验证是否分别取证？
